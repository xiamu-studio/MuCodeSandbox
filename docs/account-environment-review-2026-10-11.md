## 需要区分的事实

**服务方可能收到哪些信息，与服务方如何判断封禁，是两件事。** Anthropic 的[隐私政策](https://www.anthropic.com/legal/privacy)列出 IP、时区、系统、浏览器、设备和使用信息，也包括账户、付款及必要时的验证资料。这证明信息类别可能被收集，不证明某一个值或组合必然导致封号。

**Linux 并非这里证实的封禁原因。** [Claude Code 安装要求](https://code.claude.com/docs/en/setup#system-requirements)支持 Ubuntu、Debian、Alpine 和 ARM64，并列出 4 GB 以上内存要求。该支持范围针对 Claude Code，不能反推所有浏览器账户和所有地区都安全。

**代理可以改变远端看到的 TCP 握手。** [Cloudflare 的 CONNECT 说明](https://blog.cloudflare.com/a-primer-on-proxies/)解释：代理两侧分别建立 TCP，传递的是数据流而非原始 TCP 包。我们当前连接代理路线没有保证把客体原始 TCP 握手保留到网站；这也不意味着已经证实会触发封禁。网站 HTTPS 内容和代理外层加密仍需分开判断。

**家宽与独享需要独立证据。** traceroute 显示探测得到的网络路径；路径可能变化，也不是住宅合同或机器物理位置的证明。即使前几跳属于运营商，也不能由此确认 IP 独享、无历史滥用或所有目标均接受。这个判断依据 traceroute 的能力边界作出，参见 [RFC 1393 中传统 traceroute 的说明](https://www.rfc-editor.org/info/rfc1393/#section-1)；不采用其中已废弃的实验性新协议。加密隧道通常仍通过公网传输，不能把它描述成不经过公网。

**越南在支持名单里，不等于换成越南出口就自动获得使用资格。** 当前[访问地区名单](https://support.claude.com/en/articles/8461763-where-can-i-access-claude)包含越南；账户与实际使用仍须符合[消费者条款](https://www.anthropic.com/legal/consumer-terms)中的地区和账户要求。本文不建议编造身份、账单地址、绕过验证或把消费订阅改造成未经允许的转售接口。

**重置本地资料不能清除对方历史。** 封禁问题应走官方申诉。2025-09-15 生效的[Usage Policy 版本](https://www.anthropic.com/legal/archive/22742366-2ef0-4c7a-a833-6523f10d3944)禁止用其他账户绕过封禁。本轮发现官网 `/legal/aup` 展示的下一版标注 2026-11-12 生效，晚于本轮日期，因此没有把该未来版本直接称为当日已生效政策。

## 对照我们的实际环境

当前本机状态来自已安装应用的只读 API；配置快照见 `test-results/public-post-review-2026-10-11/local-state.json`。首页、签名、文件和实时防护验证见 [0.4.3 首页验证](browser-home-validation.md)。历史故障结果保留各自包版本，不能冒充最新包重测。

| 注意项 | 现有实现或现场状态 | 尚需注意 / 验证 |
| --- | --- | --- |
| 保护范围 | 浏览器与 CLI 在 Linux VM；Mac 管理窗口显示其画面 | Mac 邮件、Safari、其他本机程序和手机不自动受保护；系统默认打开的外部链接不能算在 VM 内 |
| 严格联网 | 当前越南 VM：严格模式和透明代理开启；防火墙、通道及有效许可核验通过 | 不使用旧开发环境的直连配置来测试保护；当前已停止的直连 VM 未改动 |
| 统一线路 | 本机专用 `127.0.0.1:24897`，单节点 MATCH，无 DIRECT 备用；未改变全局 Clash | 专用本地端口不等于专用公网 IP；供应商仍可能在节点背后轮换或按目的地分流 |
| 实际出口 | 更新后浏览器首页实见 `160.191.52.242`，IPinfo 标为越南 / Hanoi | 只证明这次查询的出口；不是家宽、独享、长期固定、目标服务同出口或声誉证明 |
| IP 锁定 | 产品有批准出口和异常停机机制 | 当前越南 VM **未启用出口 IP 锁定**；不得把“防护已核验”解释为 IP 已固定。即使启用，定时查询也不是每条连接出口证明 |
| DNS | 当前配置：`1.1.1.1`、`cloudflare-dns.com:443/dns-query`，受控 DoH 经上游 | 解析器国家与出口不同不单独构成泄漏；看请求路径、TLS 与失败回退。宿主解析代理域名等管理流量另有边界 |
| IPv6 / WebRTC / QUIC | 严格路线拒绝普通 IPv6 / UDP；浏览器限制非代理 WebRTC UDP并禁 QUIC | 是阻断策略，可能影响实时音视频；不能据此声称所有协议可用，也不能仅凭单个网页就证明全部故障无泄漏 |
| 断线与应用退出 | 默认拒绝、所属通道、8 秒左右复核、最长 45 秒联网许可 | 存在检查 / 到期窗口，不能称瞬时阻断；客体 root 完全失陷不属于外部强制边界。真实睡眠、切网和全天测试继续暂缓 |
| 时区与语言 | 当前浏览器实际显示 `Asia/Saigon`、`en-US`；VM 使用 Linux 原生信息 | 这是一套可真实检查的配置，不要求越南必须越南语。不随机换指纹或把 Linux 声明为 Mac；字体、软件 GPU 等并未保证与普通 Mac 相同 |
| 浏览器发行版 | 当前实际为 Chrome for Testing `156.0.8078.4`，ARM64 包，未自编译 | 测试专用、无自动更新；“官方来源”不等于适合长期日常登录。需选择受维护的稳定发行版，复用现成包和更新机制，绝不恢复内核编译 |
| 邮件与授权链接 | 沙箱中的页面请求经过受控网络 | 未验收完整真实授权跳转；在 Mac 邮件或本机默认浏览器中打开的请求不归 VM 控制。使用前检查链接最终打开位置 |
| 资料清理 | 浏览器重置清理本地浏览资料；完整 VM 重建清理客体应用资料 | 浏览器重置保留 Claude Code 配置；快照、同步或旧备份可能带回登录。不会删除网站服务器上的记录 |
| Claude Code 资源 | 越南测试 VM 当前 2 GiB，供无账号短测 | 低于官方列出的 4 GB 要求；正式使用前调整容量并验证浏览器和 CLI 同时运行。这是资源稳定性问题，未证实与封禁有关 |

[Chrome 官方下载说明](https://www.chromium.org/getting-involved/download-chromium/)明确 Chrome for Testing 面向测试、不自动更新；稳定渠道是日常维护方向，不能因为帖子声称某个旧版可注册就长期停留在该版本。

邮件里的远程图片或链接可能产生独立请求。[Proton 的追踪保护说明](https://proton.me/support/email-tracker-protection)解释了这种机制，但邮件防追踪不代替点击链接后的目的网站网络控制，也不能证明某封邮件直接造成封禁。无需为本轮测试另买邮箱；现有邮箱的隐私设置和链接打开位置可以单独核对。
