# 浏览器运行中防护验证

日期：2026-10-10。范围：Linux VM 浏览器，不使用 Claude 账户或付费模型。

## 已实现的检查

原有网站导航前检查保留。严格网络环境的后台管理器每 8 秒读取正在运行的浏览器保护状态；新的受管访问也检查。只读取 `mucodesandbox-browser.service` 的进程组，并匹配固定浏览器可执行文件。页面与图形进程的全部可见线程必须启用 seccomp、禁止获取新权限且没有有效特权；页面进程还必须有独立 PID 空间，禁用保护的启动参数会被拒绝。

检查失败沿用环境隔离流程：撤销浏览器画面、终端和宿主文件授权，终止任务并停止 VM，最终显示错误。并发访问共用正在进行的检查；已关闭会话的迟到检查不会隔离其替代会话。正常关闭后不再检查旧浏览器。

这是采样检查，8 秒是调度间隔，实际发现与停机还受检查和关机耗时影响；不保证瞬时发现或零时间窗口。已有网络防火墙独立限制流量，不因图形保护检查间隔而主动放行直连。客体 root 属于管理边界，不能声称本检查抵抗 root 控制内核。直接联网模式没有严格环境的后台监测，本机 Mac 浏览器也没有新增此保护。

## 验证方法

`npm run test:browser-monitor` 创建独立严格网络 VM、安装原样生产浏览器，打开真实画面与终端，并由客体读取明确授权的宿主文件。随后启动进程组之外的未保护浏览器，确认它不会误触发受管浏览器的检查。

故障注入将另一个实际未保护的图形进程放入受管浏览器进程组，等待后台检查自动发现，不主动调用管理器的监测方法。验证已有连接、未使用票据及文件授权撤销，VM 实际停机。显式重启后检查旧凭据仍不可用、绘图恢复及正常关闭。故障通过专用管理接口注入，不代表普通开发用户可以更改 root 管理的进程组。

抓包覆盖首次用户 VM 启动之后的浏览器安装、操作与故障至停机，导出保留的物理出口文件，批准代理必须有正向流量，IPv6 与未批准 IPv4 必须为零。这份抓包不覆盖基础镜像制作、VM 首次启动或恢复启动；这些范围分别使用原有专项证据。

报告、实际截图、抓包及准确源码副本保存在 `test-results/browser-runtime-monitor*`。`node scripts/verify-browser-monitor-evidence.ts` 独立重读源码指纹、各线程记录、故障记录、截图指纹和 pcap；不将截图指纹验证写成独立像素解码。
