## 对附件具体改法的修正

1. **A 组配置可做，但“做完网络十项只剩两项”不成立。** IP 类型、独享、
   每连接出口、TLS / HTTP2、头部和完整泄漏窗口仍需要不同证据。
2. **B1 不应优先当防封改造。** Ubuntu 标准桌面推荐 Liberation、Noto CJK、
   emoji、Noto core、Ubuntu 字体；多语言不是 Docker 独有。只从安装清单
   删除包不会移除旧 VM 已安装的字体，粗暴删除还会损害中文 / 多语言显示。
   [Ubuntu 官方包依赖](https://packages.ubuntu.com/noble/ubuntu-desktop)
3. **B2 不能只补一个假输出。** 44100 Hz AudioContext 当前已经运行；真实
   设备枚举、播放到 Mac、权限、停机撤销和浏览器音频数据传输是不同功能。
4. **B3 不应绕过刚完成的 Retina 修正。** 使用真实固定虚拟桌面配置可以
   稳定 screen，保留 2×；普通窗口缩放与虚拟显示屏分辨率应分别管理。
5. **B4 现在有更直接的正式包路线。** 已验证官方 ARM64 包索引与 Release
   摘要匹配，但尚未下载包或核验仓库签名。不得让 155 直接打开 156 的旧
   资料；检查点是备份，不是跨版本兼容保证。
6. **B5 不能简单在启动后关闭 autoAttach。** 源码还用会话表做尺寸调整、
   浏览器检测及生命周期管理；减少附加前必须提供替代跟踪与故障关闭方法。
7. **B6 维持 IPv6 限制及现有绘图配置合理。** 理由是实际保护和兼容性，
   不是确定这些特征不会被任何风控使用。

## 如何判断“可以进入下一阶段”

1. 来源：运行的是校验过的真实 ARM64 稳定发行版，版本 / 资源可解释，
   不靠假 UA、假显卡或假设备返回值。
2. 配置：实际语言、时区、资源、主机名、屏幕符合保存配置；对照到多个
   上下文；不拿原生的近似 / 缩减字段当冲突。
3. 网络：防护范围明确、多目的端回执一致、选定故障下关闭；缺失的外部
   证明仍标未测，不通过买线路或探针成功把它涂绿。
4. 功能：网页可用、画面清晰、资料保留 / 空白重建符合各自目标；保护
   失败不继续业务访问，恢复可回退。
5. 成本：先无账号固定响应 / 普通测试页，不付费调用，不进行一整天长测。
6. 边界：VZ / DMI / virtio / 软件 GPU 限制仍可识别。如果业务明确要求
   物理 GPU 或禁止 VM，这时应选择真实设备的执行路线，停止在字体和
   小参数上追加投入。物理设备需另有条件，本轮只记录，不更换平台。

这六项证明技术状态与可用性，不证明账号不会被风控。即使换美国线路，
也不能仅靠这套清单判断服务方的地域资格、策略或账户历史。

## 架构决策记录（方案，未部署）

- ADR-01：保持真实 Linux ARM64 VM / 原生属性。保留隔离和成本优势，
  接受系统级可识别边界；对要求物理机的业务另有执行平台，当前不实施。
- ADR-02：采用正式稳定浏览器 + 应用受控验证 / 迁移。优先官方 ARM64
  现成包；不编译内核、不把测试构建换个渠道名就当正式分发。
- ADR-03：先处理当前明确差距，功能按需求补齐。保留保护和清晰度，
  不能以删字体、造空设备或关闭生命周期管理当作可证明的风控改善。

方案供用户核对，实施 / 故障注入先使用隔离测试资料；候选验证通过后才
安排已安装应用 / 现有用户资料的迁移和必要的重启。
