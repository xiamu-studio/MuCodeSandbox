# 出口核验与变化停机验收

日期：2026-10-10。版本：0.4.0 本机候选。

## 已实现

严格透明网络环境可显式保存批准的公网 IPv4，设置不会自动采用新测量值。管理器通过真实客体 TUN 请求固定的 `https://ipwho.is/`，使用系统 CA、名称验证、干净环境与受限 JSON 回应；不使用宿主联网作为后备。

启动发布运行状态前、打开浏览器、建立终端、创建和使用客体桥接授权时重新核验。后台检查独立于界面，也覆盖正在安装软件的环境。出口变化、测量失败或未知回应会取消任务、关闭终端和浏览器、撤销桥接并停止 VM；配置变化和过期异步结果不能批准新环境。检测状态与批准设置分别保存。

## 实际证据

`npm run test:egress` 的 `test-results/egress-constraint.json` 于 2026-10-09 17:01:56 至 17:05:58 UTC 通过，包含防护 v5 的短期许可与专用检测身份，使用真实 Linux VM、TUN、认证代理、TLS、原生终端和宿主桥接，Claude 登录和付费调用均为零。旧宿主阶段报告独立保存在 `egress-constraint-before-lease.json`。

测试固定生产测量域名，但仅在测试包装器中解析到受控 TLS 服务，并使用 root 所有的测试 CA。服务返回合成的 A / B IP；**不是两个真实公网或住宅出口切换的证明**。产品没有测量 URL 覆盖入口。

- 启动回应与批准值不同时，实际 VM 停止，受管访问拒绝。
- 匹配时普通程序与桥接可用，指定物理网卡的直连拒绝。
- 安装任务和真实终端运行期间切换回应，后台检查撤销终端、未用票据和桥接，取消任务并停机；本轮耗时 10700 ms。这是一次观察，不是最坏时延承诺。
- 无效 JSON、错误 TLS 名称、测量服务中断均阻断并停机；用户数据与批准值保留。
- 五份物理抓包分别记录 25 / 346 / 114 / 53 / 52 个输出包，仅批准代理、管理 SSH 回复与 DHCP，无物理 IPv6；捕获覆盖启动核验至检测，停机前结束。VM 停止另由实际状态验证。
- `npm run test:egress-ui` 七项通过，覆盖显式保存、其他设置保留批准值、运行时只读、异常状态和 320 / 390 像素及桌面布局。此项使用模拟运行状态，不代替实际 VM 证据。
- 完整自动测试 57 项通过；配置校验、过期测量竞态、忙任务撤销、自身任务触发隔离的死锁、停机状态及许可激活 / 续期 / 退出撤销均有覆盖。

## 保留的验收脚本问题

`egress-before-capture-fix.json` 失败：抓包缓冲未及时落盘。改用即时输出、就绪检查，且诊断失败也必须执行原停机操作。

`egress-before-strict-capture-check.json` 历史字段虽为 `passed: true`，但没有任何有效抓包，不能作为通过证据，已明确标记无效。脚本现在要求五份抓包、捕获错误为空、实际停机及异常显示均正确。

`egress-before-physical-filter-fix.json` 失败：把 TUN 内部流量误计为物理外联。改为从实际默认路由取得物理接口，按该接口解析抓包；失败前先保存原始包及文本。最新通过报告独立保存。

## 仍需完成

这不是每个连接都固定公网来源的保证。客体失去宿主续期后自行断网、管理进程硬退出和首次核验前持久任务约束已有 [独立实测](guest-lease-validation.md)；仍需休眠恢复、受控真实公网分流和住宅线路验收。仅定时查询 IP 无法证明不同目的地址都走同一出口；更强保证还需要上游可强制的固定路线或连接级约束。

完整剩余工作见 [功能差距](gaps-and-validation.md)。本阶段不证明不会被封号，也未完成 macOS 虚拟机、Claude Desktop 或 Apple Network Extension。
