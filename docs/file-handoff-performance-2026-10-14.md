# 文件传入后操作等待优化

2026-10-14，0.4.39 / c0db11718fe40fa5。

## 改动与原因

原流程在上传接口返回已落盘路径后，仍等待一次完整文件列表查询，期间复制路径和返回按钮保持禁用。改为直接使用经过服务端授权和防护检查的上传回执；旧列表及分页立即失效，完整列表由用户点击刷新读取。列表故障不再把已经成功的上传显示成失败。服务端传输前后检查、两份回执要求、文件边界及停止策略没有减少。

## 实测秒数

同一真实 VM、安装版 0.4.38 后台，分别加载修改前后生产文件面板；每组 3 次 1 MiB 合成文件。计时从拖入事件到路径 / 返回按钮可用，使用浏览器 performance.now 和 MutationObserver，非电脑操作工具耗时。

| 测量 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 第 1 次 | 9.524 秒 | 6.331 秒 |
| 第 2 次 | 9.872 秒 | 5.888 秒 |
| 第 3 次 | 10.816 秒 | 6.123 秒 |
| 中位数 | 9.872 秒 | 6.123 秒 |

中位数减少 3.749 秒，约 38%。原流程附加列表查询分别为 3.811 / 4.065 / 4.550 秒；新流程没有这次请求。两组前后防火墙 / 隧道配置一致且联网许可有效。测试文件已按精确路径清理。

这是受控本地界面加实际 VM 接口的短测，不代表所有文件大小、Finder 拖入、网站上传、网页加载、线路 RTT 或屏幕帧率均提升 38%。两组未交错采样，机器负载有波动，不能把 3.749 秒视为固定承诺。
