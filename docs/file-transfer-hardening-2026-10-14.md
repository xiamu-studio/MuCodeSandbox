# 文件传输中断与本机下载检查（2026-10-14）

## 本轮发现及改动

继续优化现有 Linux 文件传输，不增加产品运行模式，也不改变网络许可和双回执门槛。

1. 上传原先直接写入最终名称。改为在 Incoming 内的私有临时目录写入并 fsync，随后用不覆盖既有目标的硬链接发布，删除临时链接后返回成功。普通写入异常清理临时文件；进程被强制杀死可能留下私有临时文件，但它不出现在传输列表，也不能通过下载接口访问。目录仍随环境完整清理；这不是断点续传。
2. 本机 0.4.31 点击下载已有 19 字节测试文件，实际返回传输失败。进一步执行同一程序捕获 `mm_send_fd: sendmsg(1): Message too long` / `mux_client_request_session: send fds failed`。文件属主、权限、大小和单硬链接均正常。固定 Python 程序从 SSH 的长参数改走标准输入，以短命令启动；同一文件随后成功读回。未采用自动重试写入或更改 SSH / 网络保护配置。该故障属于本机到客体的命令传递，不能用它解释此前公网出口 TLS 中断。
3. 在隔离进程中复现大块 stdin 遇子进程提前退出产生未捕获 EPIPE、终止 Node 服务的问题。增加 stdin 错误处理，将连接关闭报告为本次操作失败，保留取消和子进程组清理。
4. 文件大小按 B / KiB / MiB 显示，19 字节文件不再显示为 0.0 KiB。
