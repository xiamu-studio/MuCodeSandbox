# 会话固定虚拟桌面与清晰展示

日期：2026-10-11。对应设备处理方案第 5 项。此页记录源码实现与本机无 VM 夹具验证；独立候选 VM / 桌面安装包的实际结果由统一验收另记，不能与旧 0.4.5 的 Retina 证据混用。

## 行为与边界

新浏览器会话的首个查看窗口默认选择真实 **1600×1000 逻辑桌面、DPR 2、3200×2000 像素**。显示设置可以选择 1280×800、1440×900、1600×1000、1920×1080、2560×1440；固定模式始终使用原生 2× 密度。最大选项为 14,745,600 像素，仍低于 1600 万像素限额。2560×1600 @ 2、超 8192 单边或额外字段被拒绝。

选择会话固定尺寸时，通过原有受认证 RFB SetDesktopSize 更改真实桌面，并以受校验 xsettingsd 进程更新原生 DPI。现有浏览器窗口调整到桌面逻辑尺寸；不覆盖 JavaScript screen / DPR、不增加设备仿真。服务端同时核对实际 RFB 像素、原生 screen 的宽高及原生密度，错误高度不能只凭宽度 / 密度而显示“匹配”。

普通窗口缩放、打开输入栏、全屏和退出全屏仅改变查看区域，不再次改变固定桌面或浏览器窗口。**0.4.7 默认“适合窗口”**：完整展示右侧与底部，只缩小，较大窗口保留原始尺寸并留白，不把画面拉大。用户可明确选择“原始像素”，让每个画面像素对应一个宿主物理显示像素；在 DPR 2 的 Mac 上，3200×2000 画布呈现为 1600×1000 CSS 尺寸。较小查看区域此时使用滚动条裁切桌面，保留清晰度和 noVNC 的原生坐标映射。此前 0.4.6 默认原始像素导致较小窗口需要滚动，用户再次反馈后修正默认值。

桌面模式和尺寸保存于当前后端浏览器 Entry；画面重连或重新打开查看页恢复该会话设置。关闭浏览器后该设置结束，新会话再次使用默认值。旧请求省略 mode 仍按自适应处理，已运行的旧自适应会话重连保持其原行为。用户可明确切换“随查看窗口调整”，恢复随查看区域 / 宿主密度调整真实桌面的行为。

设置失败显示独立错误与重试按钮。串行操作在授权后、DPI 更新后、RFB 回执后和窗口操作间核对原会话仍存在；关闭后的迟到请求不会写入替代会话。显示错误不解除原有网络、VNC 认证、renderer / GPU 沙箱或生命周期关闭条件。

## 仍需实际候选环境核对

夹具不能证明候选 Chrome / TigerVNC 在 VM 内会正确应用尺寸、原生 DPI、screen / DPR，也不能证明安装包已包含改动。应在统一独立候选 VM 验收默认固定尺寸、每个选项、原生 screen / Worker / iframe、窗口 / 全屏 / 回切、滚动输入、正常关闭后资料保存及原有防护。

跨外接显示器 / 宿主 DPI 变化、非整数密度、多个查看窗口同时切换设置、最高预设的持续性能仍需实机验证。固定模式的宿主 DPI 变化仅调整呈现比例，不改变客体 2×；计算单元测试覆盖 1、1.5、2、3 密度，尚未当作真实多屏验收。固定模式会保留小窗口的滚动区域，用户如需要一次看到整个桌面，可主动选择缩小展示。

实现：`shared/guest-display.ts`、`server/guest-display-session.ts`、`GuestBrowserHost.resize()`、`src/GuestBrowserView.tsx`。本轮未重启生产应用 / VM、未重导航生产页面、未改变 Mac 屏幕 / 时区 / 全局代理，也未改变 CDP 附加流程。
