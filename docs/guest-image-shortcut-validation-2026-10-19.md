# 沙箱画面直接使用 ⌘V 粘贴图片

**0.4.57 / b19ac1abf82800ca 已安装并恢复原沙箱**。用户确认保存工作、结束传输后正常退出更新，安装与后续观测见文末。

## 问题与行为

用户在Linux网页输入框按⌘V得到字母v。0.4.56只接入了文件面板的paste事件；画布仍由noVNC处理键盘，macOS Command会被映射为Linux侧Alt/Super，而不是Ctrl。

本轮在浏览器和桌面共用的查看器中接入焦点画布快捷键：先点击目标输入框，再按⌘V，显式读取Mac图片、等待同一图片接口确认传入，再发Ctrl+V。无需打开文件面板或保存图片文件。不发Enter或执行提交动作；目标网站/客户端是否接收图片、是否在粘贴时上传附件由其自身决定，不能保证所有输入框支持图片。

保留文件面板“只传入剪贴板”的按钮和面板⌘V；其后由用户手动Ctrl+V。中文/翻译及其他本地文本框保持自身原生粘贴，不接管。Linux内已复制的内容仍可Ctrl+V；CLI PTY不新增图像二进制或键盘宏，CLI图片支持范围不扩大。没有Mac文字/HTML/文件路径的隐式回退。

## 边界

- 只接受真实、非IME组合中的画布键盘/图片paste事件；拦截v的down/up及重复按键。释放noVNC已发送的Command映射修饰键后，确认图片才发送Ctrl+V，避免裸v和Alt+Ctrl+V。
- 当前画布、环境、连接、窗口焦点必须保持。等待期间切换tab、断线、失焦、点击别处或继续输入会撤销自动粘贴；客户端取消请求不代表服务端回滚，迟到图片可能留在Linux剪贴板，但不会向新焦点发键。
- 提示只有小型临时状态，不改变画面布局或分辨率。读取/传输错误显示中文，无自动重试。按钮和快捷键复用同一前端传输函数与原认证图片接口。
- 所有67个服务端模块与已安装0.4.56逐字节相同；main/preload/图片IPC桥接未变。两份独立有效批准IP回执、异常断网、PNG限制、内存传图和显示服务绑定均保留。字体、语言、资源、网络配置和用户资料未改。
