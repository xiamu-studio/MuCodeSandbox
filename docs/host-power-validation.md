# 宿主休眠事件防护

2026-10-11。新增代码接入 Electron 的 suspend / resume 通知，收到任一
事件后同步关闭受保护 Linux 环境的管理访问，随后异步撤销现有连接 /
宿主授权，取消任务并沿原隔离路径撤销联网许可、尝试停止 VM。唤醒不自动重启，
需要用户手动启动并重新走完整核验。

休眠期间与异步停机期间拒绝受保护环境启动及访问；异步启动检查后、
启动 VM 前和启用业务许可前再次核验。事件到达时正在核验的旧访问不能
继续续期。该项不保护本机其他应用，也不扩展本机浏览器防护范围。

## 尚未验证

上述 a25ecde 轮是无 VM 事件注入和源码测试。下方 4227377 轮另有
真实 VM 证明；两轮都不是实际 Mac 休眠。新包不能自动继承旧包完整
串联、容量、共享或隧道专项。原 2651186 本机包保持不动；该旧包有
下方已发现的启动顺序缺陷，修复包含在新 4227377 候选。

异步通知处理不能保证在 macOS 进入休眠前完成，也不能据此保证真实
唤醒时客体的第一包必定先于通知处理被阻断。客体已有独立失效许可，
但真实宿主休眠时间 / 虚拟机时钟与首次业务包的关系尚未实测。Wi-Fi /
地址切换和全天稳定性也仍待验证。不主动休眠或关闭用户的网络。

首轮源码测试的停机替身被暂停，测试又先等待停机，导致测试等待顺序
卡住；仅终止该测试进程并修正顺序，随后针对性和全套测试通过。没有
修改产品停机策略来让测试通过。

结束后确认所属 VM / 基础镜像 / 数据全部删除。停止命令随后读取状态
时遇到已删除实例，这是清理交叠，不是 VM 仍在运行。失败报告保留为
`test-results/host-power-vm-early-fixture-restriction-failed.json`，原始记录
位于 `host-power-vm-1791650102993/`。调整测试顺序为完成官方浏览器
依赖安装后再限制线路，不修改产品防护或移除失败记录。
