# CLI Environment Audit Implementation Plan

**Goal:** 持续核对命令行客户端对虚拟化、系统环境和异常行为的读取及发送，保留可复核证据。

**Architecture:** 当前真实 VM 的只读系统观察与官方客户端审计分开。
客户端用临时空白资料和独立网络命名空间运行，禁止真实账号和外部请求。
报告区分静态代码线索、运行读取、合成接收端回执和未覆盖条件。

**Tech Stack:** Node.js、Python、Ubuntu strace、Linux namespaces、官方 npm 软件包。

## Task 1: 当前状态与官方包

- 已核对当前越南 VM 未安装 Claude Code 或 Node，原环境不安装客户端。
- 获取官方 npm 当前 Linux ARM64 原生包，验证 registry 签名、完整性及执行文件摘要。
- 文件：`scripts/audit-claude-fetch.mjs`、`test-results/client-environment-audit/`。
- 仅取一个平台；压缩下载上限 128 MiB、解压上限 400 MiB；不下载浏览器或源码工具链。

## Task 2: 静态线索

- 从可读程序段检查虚拟化探测、设备 / 系统读取、容器识别、环境元数据和请求构造。
- 不把某个字符串存在当作当前流程已经执行；记录位置、上下文、版本、摘要和限制。
- 文件：`scripts/audit-claude-static.mjs`、静态 JSON / Markdown 报告。

## Task 3: 无账号运行观察

- Ubuntu 官方 strace 仅解包到审计目录，不安装系统软件。
- 在独立 mount / network namespace 内启动客户端，空白 HOME / 配置，遮蔽原用户目录。
- 原 VM 网络、代理、防护和资料不改。命名空间仅有回环设备，无默认路由。
- 追踪文件 / 设备读取、进程执行、网络尝试与退出；任务限时、按进程组取消。
- 同一命名空间的本地 Messages 夹具返回固定内容，不转发、不调用模型。
- 校准追踪确实能看到系统虚拟化检查，否则不能把未发现当作没执行。

## Task 4: 请求与场景

- 覆盖版本 / 帮助、首次交互启动、本地无工具请求、可选遥测关闭与默认行为对照。
- 必要时检查授权后的受控本地工具任务；只使用合成凭据和审计目录。
- 区分网络尝试、实际连接和本地接收数据；不把错误路径或本地网关行为推广到真实登录。

## Task 5: 当前结论与持续复核

- 保存运行原件、客户端与脚本摘要、场景表和未完成项，更新 `docs/TODO.md`。
- 每个客户端版本单独绑定结果；更新后必须重新检查，不沿用旧版结论。
- 不修改官方客户端或伪造环境结果，不做隐藏虚拟化标记的改造。
- 登录后、官方网关、远程功能及服务方账户判断不在无账号结果的证明范围内。

用户已授权持续推进，本计划直接执行，不额外创建工作线程或代理。

## Task 6: 间接子进程与本地 MCP 权限范围

- 在相同官方客户端、无真实账户的命名空间中增加 7 个明确要求的只读工具场景。
- 对照 `Read(//sys/**)` 对直接 `cat` 与 Python 文件读取的作用；对照命令前缀拒绝与绝对路径调用；全禁 Bash 作为负对照。
- 自建几十行 Python stdio MCP 夹具，仅读取固定的系统产品名称，不安装第三方插件，不访问任意路径或网络。
- 对照 MCP 调用允许 / 拒绝，以及已配置但工具拒绝时服务启动阶段的读取。不得将夹具特意发起的查询描述成客户端默认偷偷查询。
- 修改 `scripts/audit-claude-guest.py`，新增 `scripts/audit-claude-platform-fixture.py` 和独立复核脚本；每批保留脚本及原件摘要。
- 运行前核对已有客户端摘要与没有存活的审计进程，复用缓存；各场景限时 30 秒、单文件 16 MiB，串行执行。
- 独立复核 strace 进程 / 文件读取、MCP JSON-RPC 事件、下一次模型请求中的工具结果与错误；同时核对原 VM 防护和机器标识未改变。
- 更新审计报告、项目状态和统一待办；仍不覆盖真实账户策略、所有插件或全部识别方式。

## Task 7: 已配置启动 hook 与 API 错误路径

- 延用同一缓存和仅回环的测试网络；先确认没有上轮存活进程。
- 自建 SessionStart 命令 hook，仅读取固定系统产品名并返回上下文。对照启用、禁 Bash / Read、disableAllHooks；不启用真实插件。
- 本地接收端返回合成 HTTP 400，或首次 500 后恢复 200，分别比较默认与非必要遥测关闭。保存每个实际响应状态，不推定所有错误 / 崩溃行为。
- 记录 hook 子进程、成功读取、进入首次 Messages 请求的上下文、错误输出、实际重试次数与默认事件环境字段。
- 各场景仍限时 30 秒和单文件 16 MiB；不触发真正的登录、收费、系统崩溃或浏览器更新。
- 用独立脚本核对原始调用 / 回执与运行脚本摘要，更新报告及待办；不将测试设置写入生产用户目录。

## Task 8: 当前浏览器的网页可观察标记

- 与 CLI 的版本审计分开记录，不混合统计通过范围。
- 从现有桌面只读 API 和同一 VM 的私有 CDP 通道读取实际运行信息；不新建 Manager / Store、不启动浏览器或新 VM。
- 核对实际进程 UID、版本、ELF 架构和启动参数；对现有页面的 navigator.webdriver、UA、Client Hints、语言与时区做有限采样。
- 对照页面默认 JS 世界与临时隔离世界，避免仅采信页面脚本自行覆盖的属性。
- 不导航、不创建新标签、不读取账号 / Cookie / 网页文字、不保存标题或地址，不修改指纹属性。
- 分开解释 Chrome 原生 UA 缩减行为、测试发行版和真正的自动化标记；有限负结果不证明 VM 无法识别。
- 保存运行原件及脚本摘要，核对浏览器仍运行、防护有效，更新文档与待办。

## Task 9: Remote Control 标识与无账号功能门槛

- 版本绑定地核对 Remote Control 机器标识生成、hostname 使用、桥接注册载荷和受策略控制的 host profile；静态线索不当成实际发送。
- 仅在空白 HOME / 回环网络中运行 auth status 无凭据 / 合成 API key、remote-control 默认 / 关闭非必要流量 / help、只读 doctor。
- 不登录、不伪造订阅或 OAuth、不接受开启远程控制的交互确认，不对生产资料或线路作配置。
- 保存实际退出、请求、读取与配置字段；区分“本地配置了凭据”和“官方已接受凭据”。
- 如果认证 / 特性门槛阻止进入注册阶段，明确保留该阶段未验证，不把无法进入等同于功能不存在或没有收集。

## Task 10: 精简模式与自动加载 / 显式工具

- 在临时工作目录加入仅含合成被动标记的 CLAUDE.md，对照默认、--bare、--safe-mode 是否读取及加入请求。
- 对照 --bare 下显式 hook、MCP 配置与获准 Bash 查询；不将“跳过自动发现”当成“整个进程不能查询系统”。
- 继续追踪客户端自身读取和真实请求的系统字段；所有文件、配置与工具均仅在空白测试命名空间中使用。
- 六场景均限时；不下载真实插件、不认证或收费、不把这些模式变为产品默认值。
- 记录精简模式减少和保留的能力、静态帮助与实际行为的差别；独立验证并更新文档。
