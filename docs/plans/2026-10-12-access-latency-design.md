# 0.4.13 原首次响应方案（主指标已被纠正）

需求：以毫秒查看当前线路访问网站的速度。现有 NetworkResult.latencyMs 是出口核验 / 管理命令整体耗时，不当作网页访问延迟复用。

测量：当前运行的 Linux 沙箱，以普通 dev 业务身份执行三个独立 HTTPS 请求。固定允许 Google204 和 Cloudflare trace，curl 自己计时到网站首次响应（TTFB），排除 Mac、SSH 管理调用耗时；含DNS、建立连接、TLS及网站处理，不是ICMP ping或下载Mbps。每次8秒限制，不跳过证书验证、不跟随重定向、不传账号，不回退宿主或直连。失败不伪造0ms；展示成功数量与中位数、范围和每次失败原因。

保护：调用前后核验现有防护和批准出口；检测中停止、改线路、重建或退出应用会取消，过期结果不得保存。相同环境相同站点并发请求合并，防止重复压力。结果只保留在当前进程 / 环境运行周期，线路变化清除，不复制到新环境；不做后台重复测速或大文件带宽下载。

界面：顶部防护条增加紧凑“访问延迟 / 测延迟”；网络页放站点选择、三次结果、检测时间及解释。停止时明确要求先启动，不展示旧线路速度。原实际出口的旧响应时间改名“出口核验耗时”以避免混淆。

验证：数值转换 / 中位数 / 失败、命令与站点白名单、超时和证书、前后保护拒绝、环境变化丢弃及接口认证；UI边界 / 停止 / 错误及本机真实沙箱请求。不使用真实账号或付费模型，不修改浏览器内核。

用户随后明确要Clash节点列表的值，当前主指标已改为 [统一线路延迟方案](2026-10-12-unified-line-delay-design.md)。本页保留原方案作为历史，不作为0.4.14主指标说明。
