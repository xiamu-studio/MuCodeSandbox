# 出口核验的多接收端一致性

当前安装版 0.4.7 在已经正确连接自有 VPS 后，仍于 2026-10-11 23:50:11（台北）因 IPwho TLS 握手超时隔离。该事件反驳了前一份“最终完成”判断，记录保留，不把停机归因于锁屏。

## 目标与约束

验证预期出口的可靠性，不能用取消 IP 锁定、增加直连、关闭 DNS / TLS 验证或扩大联网许可时长解决。单个公网查询端短时不可用不等于出口已经变化；需要通过仍然经过同一上游的其他独立 HTTPS 接收端核对。

方案：并行询问 IPwho、ipify IPv4 JSON 和 icanhazip IPv4 纯文本。至少两个经过 TLS 验证的有效 IPv4 回执一致才允许继续。只容忍一个明确的查询超时；证书 / 认证 / DNS / 格式错误仍拒绝。任何有效回执不等于批准 IP，或接收端间不一致，立即拒绝并取消其他未完成查询。两处超时、全部失败或少于两处有效回执均拒绝。取消和原环境的过期响应沿用原生命周期拒绝规则。

每个查询仍为 curl connect 4 秒、max 8 秒、管理操作 12 秒；三处并行，不扩大这段时长。45 秒内核许可不变。所有查询只走已有受限探针身份、受控 DNS 与唯一批准上游，无用户 curl 配置、HTTP 回退、外部直连或缓存成功回执代替新测量。

## 实现与验收

- `server/egress.ts`：并行接收端、严格解析、明确超时分类、两票一致与立即拒绝。
- `server/manager.ts`：保留 changed / unavailable 区分；公开本轮回执来源及超时端。
- `shared/types.ts`、网络页：展示本轮两处 / 三处核验结果；观察历史仍保留失败，区别单查询端失败与整个出口核验失败。
- 合成测试：三处一致；一处超时两处一致；两处超时拒绝；单个不一致立即拒绝；格式 / IPv6 / TLS / DNS 错误拒绝；探针运输失效时不发出任何查询；所有真实 curl 请求只向受控 SOCKS 发送固定接收端域名。
- 原有许可、隔离、串行生命周期、过期结果拒绝测试继续通过。
- 独立本地夹具实测缺一个回执、错误 IP、错误证书与断运输；不依赖真实账号或付费模型。
- 更新本机安装包后，对自有 VPS 重做无账号浏览器 / CLI / 多接收端检测和一次主动断线恢复；记录连续短会话，不恢复用户暂缓的全天 / 休眠 / 切网任务。

这些回执仍只证明所测接收端，不证明每条网站连接。系统整体升级、SSH 后量子交换与住宅出口仍按原范围记录。
