# 浏览器、桌面客户端和终端无缝衔接

## 目标

图形程序和命令行可以同时运行；切换页面不终止程序或重新创建画面；客户端外部登录网页在同一客体受管 Chrome 中打开，回调交回相同客户端资料。保留受控网络、按环境清理、普通关闭保存资料和无真实账户验证边界。

## 决策

1. 保留已访问的浏览器、桌面和终端页面实例，隐藏时不销毁连接。读取 / 附着现有显示可在安全的启动任务期间执行，仍检查状态、当前会话、网络、租约及进程保护；维护 / 撤销时关闭。
2. 客户端不再互相关闭；已运行时只显示窗口。轻量 Openbox + wmctrl 管理真实 X11 窗口，按受管 systemd cgroup 的 PID 选择窗口。不改变系统身份、不编译内核、不安装完整桌面系统。
3. HTTP(S) 和固定已安装客户端协议通过客体 xdg 默认处理器交给短时私有请求队列。宿主服务检查许可后启动 / 复用受管 Chrome 或将固定协议交回相同客户端 profile。禁止任意命令、file/data/javascript URL、凭据 URL、符号链接、超长 / 过期请求；不记录登录 URL 的路径、查询参数或授权码。没有宿主浏览器回退。

## 取舍与失败

隐藏页面保留连接有少量资源成本；仍最多4个VNC查看连接，4GiB并行应用压力需实际短测。网络失败保持断网；忙碌期间延迟处理链接，不能改成绕过防护的直接Chrome启动。

2026-10-12 用户明确不使用密码保险箱：官方客户端增加 `--password-store=basic`，不创建 / 解锁系统钥匙环；不卸载客户端包的系统依赖，不清空现有资料。Electron 的 basic 后端不提供安全的凭据加密，真实登录后本地令牌不能视为加密保险箱保护，只有当前 VM / 用户权限及宿主磁盘保护。[Electron 官方说明](https://www.electronjs.org/docs/latest/api/safe-storage)。本次仍不登录真实账户，未知加密旧资料不自动迁移。

## 主动文件与文字传输

查看画面工具栏增加“文件与粘贴”。Mac 文件由用户选择 / 拖入后才上传，普通客体用户写入 `/home/dev/Transfers/Incoming`；下载只列出 Incoming、Outgoing、Downloads 三个固定文件夹的普通文件，每个最多25 MiB。拒绝父目录 / 叶子符号链接、硬链接、特殊文件、路径跳转，重复名字另存。没有给 VM 开放额外 Mac 目录，重建 VM 会清除内部传输文件，Mac 原文件保留。

文字面板由用户粘贴后主动发送，沙箱 Ctrl+V 使用；反向先沙箱 Ctrl+C，再主动取回、核对、复制到 Mac。只支持普通文本，最多64 KiB，无剪贴板监听 / 自动同步。临时文本位于客体 `/run`，拥有选择权的 xclip 服务随显示停止，清理该文本；宿主预览关闭后清空。所有 API 检查当前环境状态、防护与会话，传输前后复核；不日志记录文本或文件内容。目录列表不是整个 VM 的文件管理器，项目 / 大文件可使用既有显式项目共享。

## 验证门槛

- 单元/API：运行任务期间附着显示、错误状态仍拒绝；应用互不停止；非法链接 / 大小 / 路径 / TTL拒绝，URI不进入日志。
- 隔离UI：浏览器/桌面/终端多次切换保持实例和连接；忙碌不会显示永久失败；失败后有受控恢复。
- 实际VM：浏览器和两个客户端并行，PID不随切换改变；仅关闭选定程序；普通用户出口仍为批准IP。
- 本地OAuth夹具：应用打开默认浏览器 → 受管Chrome → 同客体回调接收器取得假授权码，无真实账号；固定客户端URI确实交到相同profile。
- 本机安装包：从客户端登录按钮打开真实登录入口但不填账户；原生窗口切换 / 全屏及回到客户端正常。本机结果、限制和待办存MD。
