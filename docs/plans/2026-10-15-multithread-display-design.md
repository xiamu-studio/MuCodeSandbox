# 多线程显示编码接入

目标继续是让现有 Linux 沙箱滚动、拖动更流畅，保留6核6GiB、真实1600×1000 / 2×、当前画质、输入行为和防护策略。当前单线程显示编码约占满一核；受保护的同页对照中 TigerVNC 可见更新约14–17次/秒，TurboVNC候选约16–28次/秒，中位数约15→25。页内rAF不当成最终屏幕帧率。

采用未修改的官方 TurboVNC 3.3.1 ARM64服务端，最多4线程且不超过环境分配CPU。镜像路线不变，不改GPU名称或虚拟机信息。通过客体dev用户下载官方HTTPS归档，根控制目录复验归档与可执行文件哈希，只提取Xvnc与上游声明；不执行DEB安装脚本、不增加系统服务、不安装Java运行时。文件原子替换、根所有且不可由dev写入，重复执行不重装，有效归档可修复损坏的服务端文件。

原有显示服务及其生命周期继续持有Xvnc、窗口管理器和音频；浏览器关闭与桌面显示保持分离。显示仅绑定127.0.0.1，VNC密码认证必需，X11 TCP关闭，Xauthority由实际显示用户生成；禁用双向自动剪贴板与主选择同步。原生字体、浏览器资料、共享目录与所有出口/许可/双回执规则不变。启动失败仍走现有停止/报错流程。

独立会话已验证：拒绝错误VNC密码与缺失Xauthority、Retina尺寸切换、真实输入事件、页面和输入值在查看器重连后保留。接入前另验双向剪贴板不自动同步，以及安装的正向、幂等、损坏修复路径。之后构建、包检查并在安装版本地页面复核滚轮、滚动条拖动、显示设置、关闭重开和防护；不访问AI网站，不使用账号，不进行全天盲测。

本轮发现旧诊断脚本以root执行xauth导致认证文件被原子替换为root所有；现已改为显示用户执行并增加负向检查。生产原脚本以dev执行且现场拒绝nobody连接，未受该问题影响。旧性能记录仍可用于其原始性能范围，不能补称已经具有完整X11负向验证；新的受保护对照作为接入依据。

RFB滚轮按离散步进转发：50和150像素宿主事件在现版本都可能成为一次120像素客体滚轮。本轮不通过提高滚动倍数替代帧率优化，另保留该输入精度限制。目标未因单项性能提升而完成；GPU和进一步编码/传输优化仍按实际瓶颈验证。
