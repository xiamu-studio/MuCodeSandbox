# 本机端口暴露修复与验收

日期：2026-10-10。`npm run test:port-forwards` 的 `test-results/port-forwards.json` 于 2026-10-09 18:07:10 至 18:08:28 UTC 通过。使用无账户、无项目共享的一次性直接联网 VM，不使用 Claude 或付费模型。

## 问题与修复

旧 Lima 配置只设置全端口 `ignore: true` / `proto: any`，没有明确匹配所有客体地址。Lima 为规则补入回环地址后，会跳过监听 `0.0.0.0` 的忽略匹配，再采用默认自动映射。这使未配置的客体 TCP / UDP 服务可能出现在 Mac 本地端口；不是已证明的公网或局域网监听。

默认拒绝规则现在明确设置 `guestIP: 0.0.0.0`、`guestIPMustBeZero: false`，覆盖所有客体监听地址与两种协议。明确授权的映射只使用 TCP，宿主绑定仍为 127.0.0.1。停止的已有 VM 在正常启动前仅迁移 `portForwards`，保留其他 Lima 配置；运行中的 VM 不被直接修改，需停止后重新启动。受信基础镜像配方包含生成配置，变更后旧基础镜像不能通过新配方校验。

匹配条件可对照 [Lima v2.2.0 转发代码](https://raw.githubusercontent.com/lima-vm/lima/v2.2.0/pkg/portfwd/forward.go)。本次结论以实际服务和请求为主要证据，不只检查 YAML 字段。

## 实机覆盖

- dev 用户运行监听所有地址与回环地址的 TCP、UDP 服务，以及一个单独明确映射的 TCP 服务。先从 VM 内分别请求，证明服务都实际存活。
- 新规则下，Mac 能访问明确映射的 TCP 端口；未配置的四种服务及明确服务的未映射同号端口均无法访问。
- 仅在一次性合成环境中，直接启动旧规则作为正向对照；Mac 实际收到未配置的所有地址 TCP 和 UDP 服务回应，复现问题。
- 停止后经正常管理器启动，自动迁移新规则，重复客体服务正向对照、授权映射成功和未授权映射拒绝。
- 一次性 VM 与数据目录已清理。单元检查另外确认迁移发生在启动前，其他 Lima 设置保留且文件权限为 0600。

## 范围

这是本机端口暴露与迁移验收，不是严格出口、首次开机抓包或短期许可验收。明确授权的映射仍是宿主访问入口；不能以这次拒绝未授权映射的结果，推断授权端口也受最终公网出口批准或许可到期控制。此前只检查“忽略字段存在”的自动测试不足以证明实际没有映射，现已增加实际正反对照。
