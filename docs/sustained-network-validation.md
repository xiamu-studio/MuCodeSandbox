## 旧 b0cd06d 验收范围

脚本 `test:sustained-network` 使用固定 b0cd06d 应用包内的 40 个后台
模块，由 Node 调用真实 Lima / Apple VZ Linux VM。每轮从空白目录和
全新受保护基础镜像开始，限定 2 CPU / 2 GiB 内存 / 10 GiB 稀疏磁盘，
复用已校验的网络组件压缩包。首次磁盘余量要求 100 GiB，运行期间
保留至少 80 GiB。没有浏览器源码、编译器、真实模型账号或付费调用。

普通开发用户使用原始 TCP 连接，没有 HTTP_PROXY / HTTPS_PROXY /
ALL_PROXY 设置。一个循环每秒发起新 HTTP 请求，另一个线程持续接收
四次每秒的流式数据并在断线后重试。服务端另记成功请求、流式消息
和连接数，与客体逐条单调时钟记录交叉核对。

两段稳定阶段各至少五分钟，期间每三十秒检查真实成功请求、客体保护
状态 / 完整性 / 许可与磁盘余量。不是只在阶段开头做一次成功对照。
两段之间关闭真实代理监听并断开所有已有传输连接，确认新请求失败、
已有流和服务端计数停止、指定物理接口的绕行失败；恢复代理后无需
重启 VM 恢复，再重启 networkd 并实际续租 DHCP。

第二段后停止实际转发服务，观察管理器自动隔离并停止 VM。正常重启
必须恢复连接与防护。首开 / 恢复开机各保留一份原始 pcap 与不同
kernel boot ID；稳定阶段 / 代理故障和最终恢复阶段另有两份任务抓包。
任务抓包排除管理 SSH 回复以避免采集反馈放大；独立复核用客体原始
SLL2 接口索引 2 与物理方向过滤。未批准的 IPv4 / IPv6 输出不允许。

## DNS 与限制

初始化后测试代理只允许 `203.0.113.81:80` 的本地受控目标。运行时
受控 DoH 服务对 `1.1.1.1:443` 的请求被该测试代理拒绝，并单独计数。
本项没有验证正常域名解析，不把数字地址连接成功写成 DNS 成功。
正常受控 DNS、HTTPS 和其他协议分别由既有专项验证。

没有 Electron UI、浏览器、实际 Mac 休眠 / Wi-Fi 切换、住宅线路或
全天运行验收；也不证明对客体 root 入侵的绝对防护。十分钟及其
保护采样不能扩大为全部瞬时状态或所有故障。每轮删除自己的 VM /
基础镜像 / 数据，保留原运行环境；报告失败时仍保留失败及清理结果。
