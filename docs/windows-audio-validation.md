# Windows 数字音频链路验收

2026-10-22，Windows 预览版 0.4.66-preview.3 接入客体音频。在已连接的 Linux 浏览器画面中点击“开启声音”，将该环境的浏览器输出传到本机播放器；关闭声音、关闭显示或防护失效会撤销连接及排队声音。

本轮完成真实客体 PCM、Windows 界面播放器的静音渲染和故障撤销。实际扬声器听音、默认设备及更多设备组合继续保留待办，未计为通过。

## 实现边界

- 采集固定为 dev 身份下的 mu_browser.monitor，48 kHz、双声道、16 位小端 PCM；PulseAudio 使用带 Cookie 认证的私有 Unix 套接字及 /run 临时目录。
- Windows 使用固定的系统 OpenSSH 路径和受保护 Hyper-V 通道，核验每环境 SSH 身份及主机密钥；关闭代理/X11/本地命令转发及外部配置继承。
- HTTP 票据需要启动 Cookie、Bearer、合法 Host/Origin、有效联网会话和浏览器防护核验；WebSocket 再次核验，一次性票据绑定当前显示及联网代次。
- 音频连接只接收客体输出；客户端发送数据会关闭连接。Windows 播放器对突发到达的 PCM 清理过期排队帧并重同步，保持约 200 ms 的播放器排队边界，格式和顺序校验保留。
- Windows 使用独立控件及播放器适配，Mac 控件、播放器、Lima 和原音频传输实现保持原样。

## 11 项实际检查

独立、断网的 Windows 11 Pro VM 中，合成普通用户通过另一管理员启动的受保护代理运行当前打包后端、当前界面及真实嵌套 Linux。

| 检查 | 实际结果 |
| --- | --- |
| 1–2 | 代理与原生源摘要一致，真实 Linux 浏览器沙箱通过，并打开本地 HTTPS 页面 |
| 3–4 | 默认没有采集进程；未认证、外部来源或指定麦克风设备的请求被拒绝；缺少 Cookie 的升级消耗票据且不能重放 |
| 5 | 客体浏览器生成左右不同频率的合成音，经实际采集、SSH 和 WebSocket 得到连续 PCM；测得约 438.8 Hz、658.0 Hz，符合 440/660 Hz 测试源 |
| 6 | 关闭接收端后，实际 guest parec 进程退出 |
| 7 | 点击真实 Windows 播放按钮，实际 AudioContext 音频图渲染左右声道，测得约 445.3/656.3 Hz；音频时钟前进，宿主媒体采集调用为零 |
| 8–9 | 真实界面停止、再次开启及关闭显示，采集和播放器音频图均清理，VM 在正常显示关闭后仍可用 |
| 10 | 重新播放后实际中断本地上游，已建立音频关闭，未用票据失效，所有播放器上下文关闭，独立确认 VM Off；本次音频连接关闭约发生在注入中断后 6.6 秒 |
| 11 | 产品确认停机后删除本次专属 VM、交换机及磁盘，独立收尾确认登记和资源为空 |

播放器验收采用 Web Audio 的 [静音输出设备](https://developer.chrome.com/blog/audiocontext-setsinkid?hl=en)，让实际音频图和时钟运行，并测量渲染信号。它不产生扬声器声音，因此不作为实际听音证据。测试只保留频率、RMS、峰值等统计，不保存原始录音；不读取宿主麦克风，不访问 AI 网站或真实账号。

## 实测修复与回归

Windows 管理授权较慢，活动播放现在直接拒绝第二个连接，票据和升级边界各保留完整核验；Windows 控件允许较长的连接准备并可取消。针对 Windows SSH/渲染器回调的 PCM 突发，播放器重同步到较新的排队帧，未扩大原有共享缓冲上限。

关闭显示时，后台沙箱检查可能仍在进行。Windows 检查现在绑定原显示对象并共用在途检查，关闭或替换后的旧检查结果不再误停当前环境；当前显示的实际检查失败仍拒绝访问。专项回归分别验证了旧检查成功/失败与当前检查失败的处理。

Windows 自动测试 179 项通过，包含共享音频协议与原播放器回归、Windows 队列重同步、固定采集命令、实际子进程退出、HTTP/WS 认证、联网代次失效及显示关闭竞态。实际前后端 33 个文件与当前源码重新编译结果一致。应用资源目录 5627 个文件经过审计，160 个代码文件与打包暂存源一致，未发现私有运行文件或本机用户路径标记。

已生成未签名 0.4.66-preview.3 NSIS 预览包。运行回执、截图、账号、令牌及磁盘留在忽略目录；本机汇总为 .mu-data/windows-run/pro-audio-complete.json，包审计按版本保存在 package-audit-0.4.66-preview.3.json。失败轮次保留，重试前核对真实进程终止、原 VM Off、所有者、GUID、登记及磁盘一致，复用原盘。

独立收尾确认音频 SSH 子进程、嵌套 VM、专属交换机、登记和运行目录均为零；合成自动登录关闭，外层 Pro VM Off，安全启动与 TPM 保留。物理宿主启动时间和 Mac main 引用保持不变。正常安装桌面首启认证、实际扬声器听音及完整发布回归仍按 [Windows 工作清单](windows-work-plan.md) 继续。
