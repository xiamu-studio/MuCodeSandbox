# Windows 加密备份格式开发状态

目前已实现 Windows 专用流式加密读写模块和 33 项自动检查，尚未接入受保护磁盘导出、恢复登记、桌面向导或产品 API。它不是当前可使用的 VM 备份功能，格式仍可随完整恢复设计调整。Mac 现有备份格式和发布流程不变。

## 已实现的传输层

`server/platform/windows/backup-archive.ts` 使用 scrypt（N=32768、r=8、p=1）从用户密码及每次独立随机的 16 字节 salt 派生 32 字节密钥。密码长度限制为 12 至 256 个字符。每个档案另有 8 字节随机 nonce 前缀，配合有界记录序号生成 AES-256-GCM nonce。

档案有固定格式头、加密配置记录、最多 1 MiB 的逐块磁盘记录和最终提交记录。格式头、序号、记录类型和长度都参与认证；最终记录绑定完整磁盘长度和 SHA-256。读入只在当前记录标签验证后写出该块，要求最终提交正确且立即到达 EOF。错误密码、篡改、删除、重排、重复、不同档案拼接、截断和附加字节均不能得到成功返回。

配置只接受受限 AMD64 Hyper-V 环境、严格透明网络及出口约束；拒绝 Mac 架构、端口映射、挂载授权和未知顶层字段。读入长度在分配记录正文前验证，磁盘声明有固定上限。读写支持取消、迭代器关闭和下游写入失败；派生密钥及处理过的临时明文缓冲区在结束路径清空。

调用方必须将解密输出保存在新的私有临时文件中。部分记录成功不代表整个档案完整；只有函数成功返回，且原生磁盘/配置检查也通过后，才允许发布。不得将输出直接写入已有磁盘或活动 VM。当前模块不授予宿主路径、磁盘句柄或原生代理权限。

## 还需实现与验证

- 固定原生操作读取已停止、已登记、身份核验且独占保护的磁盘，撤销联网并保留原盘；禁止任意管理员路径读取。
- 将客体管理身份和恢复所需资料纳入加密内容，设计新机器/当前用户的 DPAPI 重新保护、冲突拒绝及完整恢复边界。
- 新私有 staging、容量准入、取消/失败清理、认证完成后发布、原生 VHDX/父链检查以及中断恢复。
- 明确保存位置、密码确认、进度、取消和恢复审阅的 Windows 产品流程，不在日志或 URL 中记录密码。
- 真实 Linux 数据与管理连接的备份/恢复读回、错误密码/损坏/空间不足/进程退出验证；跨架构和快照支持仍单独待办。

自动检查使用合成内存数据，覆盖多块及任意输入边界、敏感配置不以明文出现、随机性、逐段篡改、拼接、顺序、长度、最终提交、取消及 I/O 失败。它们不替代真实 VM 备份或恢复验收。运行：`node --test tests/windows-backup-archive.test.ts`。
