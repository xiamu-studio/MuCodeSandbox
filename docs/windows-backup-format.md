# Windows 加密备份格式开发状态

目前已实现 Windows 专用流式加密格式及受保护原盘读取，恢复登记、桌面向导和产品 API 尚未接入。它不是当前可使用的完整 VM 备份功能，格式仍可随完整恢复设计调整。Mac 现有备份格式和发布流程不变。

## 已实现的传输层

`server/platform/windows/backup-archive.ts` 使用 scrypt（N=32768、r=8、p=1）从用户密码及每次独立随机的 16 字节 salt 派生 32 字节密钥。密码长度限制为 12 至 256 个字符。每个档案另有 8 字节随机 nonce 前缀，配合有界记录序号生成 AES-256-GCM nonce。

档案有固定格式头、加密配置记录、最多 1 MiB 的逐块磁盘记录和最终提交记录。格式头、序号、记录类型和长度都参与认证；最终记录绑定完整磁盘长度和 SHA-256。读入只在当前记录标签验证后写出该块，要求最终提交正确且立即到达 EOF。错误密码、篡改、删除、重排、重复、不同档案拼接、截断和附加字节均不能得到成功返回。

配置只接受受限 AMD64 Hyper-V 环境、严格透明网络及出口约束；拒绝 Mac 架构、端口映射、挂载授权和未知顶层字段。虚拟容量为 16–256 GiB，磁盘文件长度另允许 1% 或 64 MiB 的格式余量（取较大值），并以 260 GiB 为固定外部上限，避免误拒绝已接近最大容量的 VHDX 元数据。读入长度在分配记录正文前验证。读写支持取消、迭代器关闭和下游写入失败；派生密钥及处理过的临时明文缓冲区在结束路径清空，派生失败时也清理已生成的明文元数据缓冲区。

调用方必须将解密输出保存在新的私有临时文件中。部分记录成功不代表整个档案完整；只有函数成功返回，且原生磁盘/配置检查也通过后，才允许发布。不得将输出直接写入已有磁盘或活动 VM。当前模块不授予宿主路径、磁盘句柄或原生代理权限。

## 已接入的受保护原盘读取

内部原生接口只接受当前登记的环境 ID 和短期读取会话，不接受源路径、输出路径或其他用户 SID。开始前核验原 VM 为 Off、GUID、原磁盘标识与文件身份一致、Private 交换机和拒绝规则完整、无快照/差分父盘/其他 VM 引用，以及没有待完成扩容或构建器权限。核验前后保持磁盘与目录句柄，拒绝链接及异常权限；原盘没有写入、转换或替换。

每个受限代理同时最多一个读取会话，记录文件长度与 SHA-256。原生操作互斥使其间的启动、删除、扩容、重建和管理通道操作拒绝；状态与停止仍允许。设置 60 秒空闲和 1 小时总时限，并在控制器退出、电源或资源撤销时关闭句柄。开始核验也使用独立防护取消令牌，不能因完整磁盘哈希而阻挡同一用户其他 VM 的故障清理。

数据可通过有序 32 KiB 块读取；实际导出使用独立二进制命名管道，避免每块建立 JSON 请求的开销。管道使用随机名称和受限 ACL，在发送任何磁盘字节前核验握手、原控制进程 PID、已绑定进程存活以及调用者 SID。不同进程即使属于同一普通用户且知道管道名，也不能接收数据。失败或断开后只关闭对应的旧读取会话，不能误关闭之后创建的新会话。

Windows 读取器校验回执、顺序和长度，只连接固定命名形式的本地管道；拒绝任意路径、重复消费、提前 EOF 和不一致数据。取消、上游错误及停止迭代均释放读取权限。加密档案仍要求完整提交和最终摘要成功，不能把只读流结束当作完整 VM 恢复成功。

## 真实隔离 Windows 验收

在网卡断开的评估 Windows 中，以普通用户控制器及另一管理员启动生产代理，完成 17 项实测。使用全新合成 Linux 和本地合成配置，业务许可始终关闭。

| 阶段 | 结果 | 检查数 |
| --- | --- | --- |
| 原盘准备 | 创建真实 Linux，dev 写入随机 canary，确认停止 | 2 |
| 读取与加密 | 拒绝任意路径和未登记 ID、活动 VM、启动/删除/扩容/重建/通道冲突、错误会话及跳跃偏移；取消释放；真实另一普通用户进程无法接收管道数据；完整加密、错误密码拒绝、解密摘要及原盘不变核验 | 11 |
| 正常重开与清理 | 新会话保留原 GUID，启动原盘读回 Linux canary，确认业务关闭，清理专属资源 | 4 |

实际 VHDX 文件为 5,473,566,720 字节。解密只写入新合成 staging 文件，最终 SHA-256 与原生固定句柄核验的原盘摘要相同。该文件未导入为 VM；此轮不是完整 VM 恢复验收，不能将原盘重开当作备份恢复成功。管理身份打包、恢复登记、产品保存位置及界面仍是上方待办。

独立管理员确认合成加密文件和明文 staging 均已移除、VM/登记清空、关闭合成自动登录后外层评估 VM Off。16 个相关执行文件与当前源码/编译产物逐一比对，安装中的代理摘要还与完整原生及脚本输入集合匹配。复核入口为 `node scripts/windows-backup-read-evidence.ts`，本机忽略结果 `.mu-data/windows-run/clean-host-backup-read-complete.json` 指向私有回执。物理宿主启动时间和远端 `main` 不变；没有访问 AI 网站或外部翻译服务。

首轮逐块 JSON 读取完成了真实加密往返，但吞吐不适合大磁盘，记录作为校准保留。二进制轮次的首次完整摘要核验发现测试载荷未同步所有代理输入，因此没有作为当前代码通过证据；暂存器现复制完整编译输入，重新创建合成案例后才取得上述通过结果。Windows 的目录长度在写入句柄关闭前可能仍为零，进度观察改用独立只读句柄查询实际文件长度；没有因此重启或覆盖活动案例。

本轮是源码后端验收，尚未生成包含这些原生读取操作的新预览包；`preview.12` 的安装及恢复界面记录仍对应其原载荷。
