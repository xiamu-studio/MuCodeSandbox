## 私有试运行

同一受保护会话、环境配置、防护摘要、两个不同接收方的相同出口回执及root事务epoch/检查点绑定必须贯穿验收。先关闭普通浏览器，再准备固定显示服务；候选条目没有普通查看器、音频、导航或票据入口。取消、配置变化及会话替换后的迟到回复不能取得验收凭据，也不能向替代会话发送停止操作。

候选使用带epoch的临时systemd服务，采用固定参数数组、exec服务类型、关闭环境变量展开及自动收集；不发布持久候选启动器或单元文件。启动root门在共同安装锁内核验完整检查点、候选组件、原资料目录及网络租约，资料偏好由降权dev子进程通过继承的目录描述符处理。最终清空附加组，设置三组真实/有效/保存uid与gid，再以dev执行固定空白页命令；安装锁描述符在成功exec时关闭。AppArmor策略从标准输入装入，对应固定候选路径。参数机制依据[systemd 255文档](https://www.freedesktop.org/software/systemd/man/255/systemd-run.html)，标准输入与替换策略依据[Ubuntu AppArmor手册](https://manpages.ubuntu.com/manpages/noble/man8/apparmor_parser.8.html)；具体发行版的实际行为仍待Linux验收。

dev偏好程序只处理有界Preferences与固定Downloads目录。拒绝重复JSON字段、异常命名空间、硬链接或不安全对象；用独占重命名发布自己的新文件。未完成的输出与旧偏好留在资料内，由原资料检查点负责恢复，不由子进程猜测删除。其他Cookie、Local Storage和IndexedDB文件不作为偏好处理目标。

私有CDP必须报告精确候选产品版本，且只有独立空白页；沙箱检查绑定本次临时服务的cgroup与批准可执行文件。生产本地检测协调器在自己的临时上下文中，通过Fetch接管固定虚构来源，并以不可用本地代理阻断其他访问，检查页面/Worker/iframe身份与非空画布、GPU和屏幕结果；固定合成登录和模拟消息没有真实账号或付费请求。检查后确认临时上下文销毁、空白页未变、实际版本与沙箱仍匹配，再更新防护检查。

## 停止、提交与迟到命令

候选需确认正常Browser.close连接关闭，再执行不继承取消信号的独立root停止。仅接受原epoch、检查点绑定与当前boot；网络租约失效仍允许停止。已停止候选的Last Version必须由dev程序通过钉住的描述符读出，精确等于候选版本。仅停止成功不能替代身份、渲染和沙箱验收。

root停止在共同锁内独占写入并同步固定trial-stop标记，记录本次epoch与检查点绑定，随后停止浏览器及显示。启动前与偏好完成后的门均拒绝任何已存在的停止标记，因此早先的systemd-run命令即使在停止回执之后才到达，也不能重新执行候选。部分写入同样封锁启动。有效标记才允许结束验收与绑定提交；损坏、错误绑定、硬链接或外来标记会保留供恢复处理。事务清理先核对标记，再删除自己的已知标记；不认识的字节留在归档事务并报告清理警告。

验收凭据只存在于当前进程的私有WeakMap，客户端没有可拼装的验收JSON。它绑定原会话、配置、防护摘要、root检查点和单调时间，30秒内一次性消费。新验收、关闭或撤销会作废旧凭据；提交期间由同一环境的提交任务占有，阻止新验收重入，退出也等待原提交任务收尾。提交再次检查root停止标记、停止浏览器、同步并复核资料版本，然后沿用先写入不可回退的提交决定、再发布版本选择的顺序。提交派发后才到达的取消不会推翻已确认的root提交回执。

完整管理层仍需处理提交回复丢失、进程重启和取消后的持久决定对账；不能把丢失回执当成可以回滚已提交资料。普通浏览器仍被未完成采用事务围栏挡住。已打开普通查看器的复用路径也新增选择复核，防止绕过版本检查。
