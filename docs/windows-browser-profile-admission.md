# Windows 浏览器资料版本与启动准入

Windows 设置页原先只展示批准组件的安装版本，恢复来的资料来自更高版本时仍可能看到“与已批准版本一致”。启动代码虽检查 Last Version，却通过路径再次读取，且检查未进入最终 systemd 启动器。本阶段补齐资料状态与三处固定程序检查，保留组件状态和资料状态各自的含义。

以 dev 用户、隔离 Python 运行固定路径检查。逐级使用相对 no-follow 目录句柄，核对 root/dev 所有权及禁止其他用户写入；版本文件要求普通单链接、归属 dev、不允许他人写入、1–256字节，读取后再次核对原句柄及目录项。仅交付严格四段版本，不读取 Cookie、密码、历史或项目。路径替换、硬链接、权限异常、特殊文件、格式损坏、迟到出现或状态变化均拒绝，root 调用同样拒绝。

设置页将资料分为尚不存在、未留版本记录、版本兼容、更高版本及无法信任。组件/资料放在同一客体观察中，原会话或最终网络许可失效时整个结果丢弃，避免拼接不同会话的结果。更高版本资料不触发组件修复、资料清空或自动降级；页面说明保留资料、使用匹配版本应用或新建环境。缺少记录保持既有启动语义，但明确显示未知，不能记为兼容证明。

启动在创建显示服务前检查一次，写偏好设置前检查一次，最终 dev 启动器在执行 Chrome 前再检查一次。较新或无法信任的记录拒绝打开；恢复、停止、取消或换会话的迟到检查不能继续启动。检查不保证阻止拥有同等客体用户权限的程序在检查结束后继续修改资料；真实 Linux 权限、链接/句柄语义、服务与 Chrome 运行行为仍待实机验收。

这不是在线浏览器更新或完整版本/资料恢复交付。资料检查点、跨版本升级/回滚、缺失记录的更完整来源证明以及真实恢复启动闭环仍待完成。桌面继续暂停，实际安装版保持 preview.32，候选44保留；本阶段不运行应用、安装器、管理员代理、真实 VM 或账号。
