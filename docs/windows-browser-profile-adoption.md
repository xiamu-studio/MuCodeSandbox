## 写入与恢复

固定root控制目录内的双槽记录保存原组件、资料父目录和原资料目录、归档、空间预留、未发布恢复目录及新旧选择文件的原身份。初始化完整记录后才发布活动目录；准备过程中退出留下的目录也进入可见保留记录。最多保留两代需要处理的数据，单次目录检查有256项上限；未知对象保留并拒绝。

资料内容由固定Python程序以dev身份处理，继承已经打开的目录描述符，不接收用户路径或shell片段。程序要求父进程死亡信号和禁止转储，在目录内按no-follow描述符读写，拒绝符号链接和特殊文件，恢复文件及受保护控制文件另拒绝硬链接；只有根目录的三个Chromium单例对象明确排除。归档限100000项、单路径1024字节、路径总量4MiB和内容1TiB，输出另有总量与时间上限。原项目目录不进入资料归档。

开始时停止并确认浏览器，要求已有、格式有效且不高于原批准版的Last Version。缺少记录不能作为跨版本回退兼容证明；目前不创建全新资料层级。准备就绪后另写入trial决定，候选才可由后续控制器打开。ready或checkpointing阶段恢复只终止本次尝试，不替换原资料。

未提交trial的恢复会先停止浏览器，复核原组件、归档和各原身份，将检查点恢复到原来创建的未发布目录。已有文件只允许与归档一致的前缀继续写，不截断未知数据；完整核对后持久记录恢复就绪，再以不覆盖的重命名保留升级失败的资料目录并发布兼容资料。两个目录切换之间退出也能按原身份接续。保留的失败资料会产生告警，后续需要显式采用/放弃流程处理。

提交前重新验证候选、资料身份以及同一session/boot的实际网络许可。先持久记录committed决定，再发布版本选择。提交后的重开完成新选择并保留新资料；清理失败或存在未知文件只保留告警，不回滚。日志之外的文件变更、陌生目的目录、旧组件变化、错epoch或过期许可均拒绝继续。

普通启动前的资料核验、组件修复和资料重置已经增加未完成事务围栏。当前启动器还不支持新选择，因此也拒绝它尚不能正确处理的选择记录；后续必须先实现选择感知启动，再接入版本采用。
