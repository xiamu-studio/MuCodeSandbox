## 共用画面连接层（仅源码）

从WindowsBrowser拆出`display-transport.ts`，浏览器委托其管理一次性票据、WebSocket和连接配额；不启动任何客体程序，也不授予联网许可。保持32张待连接票据、每环境4个和全局16个画面上限、二进制帧及原缓存限额。待核验的连接也占配额，已关闭槽位可重新使用。

票据绑定精确入口对象和防护会话。等待核验途中撤销、入口替换、授权失效或票据过期均拒绝，拒绝发生在建立客体流之前；撤销会关闭已连接画面，关闭服务后迟到核验不能重新建立连接。入口对象用WeakMap保存撤销代次，不按历史环境ID无限保存墓碑。只接受单一ticket查询字段，拒绝重复、额外字段、错误路径和缺授权请求；客体流创建失败时退休空连接组。

## 独立显示所有权与服务驱动（仅源码）

`display-lifecycle.ts`将准备、使用者、帧流、撤销和停止分开。凭据通过WeakMap绑定原入口，复制/序列化的对象不能释放别人；合法旧凭据的迟到释放也不会关闭替代入口。准备时按原会话对象核对，即使新旧会话ID文字相同也不接纳。不同使用者共用准备，但取消某一个不会取消仍在等待的其他使用者；取消最后一个会撤销流并等待必要的独立停机。确认失败优先返回停止未确认，保留准备失败的cause，不能因收到取消而报告成功。

已有显示的新增/重复使用仍做准入和服务核验，真实防护检查失败立即撤销画面。服务核验按入口共享，单个请求取消不取消其他已取得的使用权；撤销后迟到结果拒绝。关闭操作合并同一次实际停止，所有等待者得到相同失败；停止未确认阻止新的准备，原会话下显式重试确认后才解锁。新会话不采用旧失败回执，也不向它重放旧停止操作。生命周期状态只表示画面是否可用，不是VM Off证明；独立画面永远不冒充Chrome正在运行。

`display-guest.ts`准备固定AMD64显示组件，不读取浏览器profile或启动Chrome；复查显示服务单元、启动器字节/大小/权限、systemd用户/组/控制组及MainPID，核对proc实际UID、有效能力、控制组和进程启动身份，前后事实变化拒绝。组件本体核对固定TurboVNC摘要与root目录/文件权限。现有启动器拆为可校验函数，原完整启动命令在1/2/4/8 CPU样本下逐字一致，原源代码转换也已核对，无其他浏览器启动逻辑更改。

初版独立停止沿用同时停止Chrome和显示的命令；“从未存在Chrome服务”的新回归21项中20通过/1失败，保留原错误后修正为只停止并核对自己的显示服务，检查ActiveState与MainPID。不能要求桌面用户先打开一次Chrome才能正常关闭显示。

本轮联合122项是源码/普通进程/真实本机WebSocket及显式客体适配验证，不是完整Windows套件。服务检查20场景使用普通Windows文件和真实硬链接，root/POSIX权限、proc及systemd响应明确适配，文件和合成账号哨兵保持；不等于真实Linux权限或systemd验收。无新构建、安装包或升级，没有真实Linux/Hyper-V/客户端/听音测试。
