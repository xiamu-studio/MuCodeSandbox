# Windows 资源与电源保护的独立关闭

2026-10-26 后台源码记录。实际安装仍为 preview.32，候选安装器仍为 preview.44。桌面操作继续暂停，本轮不发起真实 Hyper-V、休眠、唤醒或管理员操作。

## 已确认的问题

原资源和电源保护在每个环境上依次取得 `VmGate` 并执行 `RecoverAllocation`。一个已停止环境的完整副本事务可以长时间持锁；某次供应程序查询也可能停留到超时。两者都能使后面的运行环境迟迟无法执行关闭核验。上一轮“运行中删除旧快照”的独立通路只解决它自己的任务，不能据此推断所有停机磁盘事务都不会影响其他环境。

## 修改

两个保护入口共用 `MuEmergencyStopSet`。队列最多容纳32个受保护环境；同一环境最多一个任务，本轮保护任务总共最多4个实际关闭核验线程，避免新增32个PowerShell进程加重低内存压力。环境锁使用不等待的尝试获取；忙碌时该环境保持未确认并稍后重试。慢供应程序留在自己的线程中，不串行等待其他环境。异常或线程启动失败不确认停止，并按至少一秒间隔重试，不重复已确认的同一归属。尚未尝试的环境优先于失败重试，避免反复失败的4个目标长期占住所有名额。

队列来源仍是当前所有者的受保护登记。每项携带规范环境ID与登记值的SHA-256；真正取得环境锁后再次核对当前所有者及登记摘要。只调用原 `RecoverAllocation`，继续保留已有平台标识、固定路径、供应程序停止回执与登记更新校验。未新增绕过环境锁的磁盘/配置写入，也不扩大为关闭未登记或其他用户的VM。

成功只缓存到准确的登记摘要；变更后的归属不能复用旧成功。旧工作尚在执行时，同ID新归属不会并发启动另一线程；退休工作仍占用容量，直到原工作结束，防止反复更换目标制造无界线程。输入、数量、摘要或重试时钟不符合边界时拒绝派发。

资源保护与电源保护保留各自的关闭状态，共享每个环境的工作结果。只要任一当前目标忙碌、失败或仍在核验，就不能显示全部停止；运行中标记直到全部确认才结束。资源/电源原有取消、通道关闭与禁止新运行的围栏保持。

## 验证范围

测试编译完整生产 `Resources.cs`、`PowerProtection.cs`，以及实际的所有者核验、参数生成和 `RecoverAllocation` 方法。供应程序、宿主指标、通知源和登记持久化使用临时文件适配器；实际执行主机线程、环境锁、普通文件写入、取消、共享任务和状态收尾。

已覆盖32个目标、最多4个实际并发工作线程及两路同时调用、持锁的停机副本、卡住的供应程序、错误停止回执、原归属变更、异用户登记、容量回收、线程启动失败和重试节流。首轮仅夹具未初始化字段的编译警告，随后明确初始化夹具字段；没有放宽编译器检查或修改产品边界来通过测试。首轮全量还发现纯扩容策略夹具意外带入新增辅助类，现将共享辅助类移到原纯策略边界之后，保持原策略夹具无需额外依赖。

全量与编译副本的最终结果、冻结输入和清理记录存于当前 Codex 工作区 `outputs/emergency-stops-evidence.json`。
