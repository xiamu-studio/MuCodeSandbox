# Windows 文件与剪贴板的会话边界

2026-10-22，在 Windows 分支审查中复现并修复一次旧操作跨越环境重启的问题。改动限定 `server/platform/windows/service.ts`，Mac 服务、共享文件交换实现及版本号不变。

## 问题和修复

剪贴板写入包含准备目录、传入文字及启动剪贴板服务等多个管理命令。原实现会撤销在途命令，但如果底层命令与撤销竞态而迟到返回成功，后续命令会重新核验当前环境并继续执行。重启后的新会话可以通过这次核验，导致旧文字进入新会话；操作最后因环境时间戳不同而报错，不能撤销此前已经执行的写入。

修复将每次交换授权返回的独立环境对象，通过弱引用表绑定到原网络会话对象。授权核验前后、命令准备完成和实际执行完成后都检查原会话身份；原会话不再活动、环境正在执行其他任务或已经停止时拒绝继续。每个命令完成后也检查合并的取消信号，不能依赖底层一定会以取消错误结束。单次操作的所有命令共用原授权对象，不能在后续步骤切换到新会话。

## 本地回归证据

`tests/windows-service.test.ts` 的四项用例使用实际 Windows 服务、DPAPI/SQLite 工作区、管理器和联网许可状态机，以及不会创建 VM 的合成后端。每次先启动、暂停旧操作、通过正常管理器停止并重新启动环境，再释放迟到结果：

- 剪贴板首条命令完成：取消信号已撤销，即使后端仍返回成功，也不能再传入文字或启动下一步。
- 剪贴板授权完成：此时尚未登记在途命令，不能只依靠取消广播；旧授权也必须拒绝执行。
- 文件下载命令完成：旧结果不交付。
- 文件下载授权完成：旧请求不能在新会话执行。

四项均核对新会话仍活动、旧操作忙碌状态已清除，且新的明确操作可以成功。修复前的剪贴板命令完成用例失败：预期仅有准备命令，实际执行了全部三条命令；因此原实现最后报错并不足以证明未写入新会话。

Windows 全套自动测试 211 项通过，类型检查通过。文件交换、图片剪贴板、翻译和原生文字剪贴板的相关回归另外通过；所有内容均为合成数据，没有外部服务请求。

独立 Pro 普通用户使用真实受保护 Linux 和 X11 剪贴板完成 8 项检查：

1. 从固定图形基盘启动 Linux 和空白浏览器，通过沙箱和网络核验。
2. 真实完成剪贴板目录准备后，仅在诊断适配器中延迟命令返回；确认原 VM 停止、重新启动后释放结果。旧操作返回 409，旧文字写入命令执行次数为零，客体中不存在旧文字文件。
3. 新的明确 API 操作成功写入并读回完整中文、emoji 和合成标识；实际文字写入次数为一。
4. 在授权完成但尚未登记在途命令时延迟下载；再次停止、启动 Linux 后，旧请求返回 409，没有执行实际下载命令。
5. 完成真实文件读取后延迟结果，再次停止、启动 Linux；旧请求返回 409，响应没有文件内容。
6. 新的明确下载请求读回原磁盘上的完整文件，操作忙碌状态已解除；共经过三次停止、启动。
7. 产品日志中没有合成剪贴板文字和文件内容。
8. 确认删除原 VM、专属交换机和受保护磁盘登记。

诊断延迟只用于确定竞态时点，所有停机、启动、客体命令和文件/剪贴板内容核对均实际执行。测试不访问 Windows 系统剪贴板，不把 Linux API 读写计为 Windows 桌面剪贴板手势或真实输入法通过。

独立操作者持有实际控制器与代理进程句柄，确认退出后才接收结果。结束后的核查确认：嵌套 VM、专属交换机、登记和运行目录均为零，登记双副本相同，VMMS 运行。5 个实际后端文件的摘要与安装包暂存载荷、本地编译产物和初始输入逐一匹配；诊断源码也与实际执行文件匹配。物理宿主启动时间及远端 `main` 未改变，外层 Pro 保持运行且网卡断开，未访问 AI 网站或外部翻译服务。
