# Windows 沙箱文件管理器入口

源码接通与 Mac 相同的客体 Thunar 文件管理器，在现有沙箱画面内打开目录。当前运行的 `preview.10` 测试包不包含此入口，真实窗口、重命名、移动和删除操作仍待后续验收。

## 使用方式

先在软件中打开浏览器画面，再到文件面板选择下载、传入或导出目录，点击“在沙箱中打开文件夹”。收到成功回执后切换至沙箱画面。文件操作在 Linux 内完成，不启动 Windows 资源管理器，不要求进入外层 Windows 测试机桌面。

旧服务没有 `fileManager` 能力时隐藏入口；画面尚未就绪时禁用并提示。切换环境或目录后，迟到回执不能把新界面切走。接口只接受受限的 `zone/path`，拒绝宿主路径和项目共享标识，Windows 持续共享仍未开放。

## 边界与取消

沿用共享 `GuestExchange.openFolder`，不改动 Mac 实现。启动进程固定为客体 `dev` 用户与组，清空继承环境，使用固定 Thunar 路径和独立 systemd 单元；单元绑定图形服务，停止客体图形服务或 VM 后随之回收。仅隐藏或切换软件画面不等于停止服务。路径解析继续使用客体目录句柄及链接检查，文件管理器保留普通 Linux 用户权限。

Windows 服务复用文件传输互斥、原会话绑定、全局在途上限和防护撤销。请求断开会取消启动链路，原会话停止或重启后，迟到的第一步结果不能继续在新会话执行后续启动命令；已打开的客体窗口不做推测性撤销或文件删除。

## 检查范围

新增真实 Windows 本机 API 的合成后端回归，通过 Cookie/Bearer/Origin、画面前置条件、未知字段拒绝、固定 dev/systemd 参数、HTTP 断开取消及跨重启迟到启动拒绝。没有启动真实图形程序，不能计作 Linux GUI 验收。

Playwright CLI 的 5 项产品组件检查通过：画面要求、明确打开、子目录路径、迟到确认不切换新环境、能力隐藏与窄屏。原有 8 项目录创建界面检查也通过，Windows 全套源码自动检查 228 项通过。本轮仅使用本机合成 API，没有操作宿主文件管理器或访问 AI 网站。

当前 `preview.10` 持续运行包保持冻结，源码检查不重建其编译产物。待该轮结束后，再构建含入口的新测试包，验证真实 Thunar 画面和文件创建、重命名、移动、删除及关闭回收，之后更新工作清单。
