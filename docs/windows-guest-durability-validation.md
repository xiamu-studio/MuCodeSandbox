# Windows 首次启动持久化与多卷压力验收

2026-10-22，Windows 预览版 `0.4.66-preview.7` 修复首次初始化资料尚未落盘就开放业务的问题。新建环境很快遇到资源临界保护时，必须立即停机；管理身份和下次启动所需资料应在开放业务之前持久化。

## 实际发现与修复

在独立、网卡断开的 Pro 测试机中，先验证业务 HTTPS 请求和 TLS 长连接，再实际降低工作卷可用空间。原生资源保护正确关闭连接并确认 Linux Off，但新控制器恢复原盘时 SSH 失败。

保留原 VM 和磁盘，等待该次启动按自身期限结束并确认控制器、代理均退出，没有因为观察超时重复启动。虚拟控制台显示 Linux 已到达登录界面。随后仅用只读解析器查看停止的 VHDX，禁止原盘写入和替换，并核对检查前后整盘摘要一致：SSH 主机密钥及 cloud-init 网络缓存为零字节，后者在恢复启动中产生 JSON 解析错误。失败原盘、管理资料、数据库和回执已校验归档；清理夹具时没有将失败恢复改记为通过。

Windows 配置流程现在先等待 cloud-init 完成，再准备防护规则；初始化失败即拒绝开放业务。在返回联网激活令牌前执行同步，将管理身份、初始化缓存及持久启动防护配置落盘。重启后的业务许可仍需重新核验，临时联网许可不作为持久状态保存。修改仅位于 Windows 后端，Mac 的 Lima/VZ、Swift 与发布架构未接入该流程。

## 修复后的真实验收

使用已构建并审计的 preview.7 程序，在同一隔离 Pro 中新建夹具：独立 8 GiB VHDX 挂载为第二个实际 NTFS 卷；其上再建一个 256 GiB 动态虚拟磁盘，附给始终 Off、没有网卡的旁观 VM。受保护工作 VM 的原盘位于工作卷。格式化前逐项确认新 VHDX 路径、容量、映射磁盘及非系统/非启动属性，物理宿主磁盘不参与格式化。操作流程参考 [Microsoft 的 VHDX 示例](https://learn.microsoft.com/en-us/powershell/module/hyper-v/new-vhd)。

| 阶段 | 已验证结果 | 客户端检查数 |
| --- | --- | --- |
| 创建与流量对照 | 当前包后端启动真实 Linux；另一卷 256 GiB 虚拟容量不占用工作卷增长预留；接收端观察新请求、既有 TLS 流和独立控制请求 | 3 |
| 另一卷低空间 | 实际可用空间降至低于 2 GiB，工作卷仍充足；VM、连续新请求与旧 TLS 流正常，原生资源保护未误触发 | 1 |
| 工作卷低空间 | 实际工作卷低于 2 GiB；未修改生产阈值，原生保护确认 VM Off；新旧业务流保持静默，独立控制请求继续成功 | 2 |
| 释放压力 | 空间恢复后旧原生授权和应用访问继续拒绝，不能自动恢复业务 | 1 |
| 新控制器恢复 | 新进程/新权限代理启动同一 GUID 的原 VM，重新核验网络、读回已提交中文文件，再删除专属资源 | 2 |

共 9 项通过。填盘请求绑定实际普通用户进程、随机令牌和精确 VM 身份，拒绝未知动作、调用方路径及错误身份；只有匹配的夹具文件可释放。工作卷填充量另受物理宿主剩余空间上限约束，压力文件有超时检查和独立 finally 释放。

强制停机后、恢复启动前，再次只读核验原盘：SSH 私钥、公钥及初始化网络缓存均已非空，原盘摘要不变。只读解析不会回放 ext4 日志，因此测试文件是否保留以实际恢复启动后的读回为准；本轮测试文件明确 fsync 文件及父目录，不把未经提交的写入当作持久数据保证。

## 收尾与证据

旁观 VM 的 GUID、磁盘标识及整份 VHDX 摘要保持一致。最终独立检查确认工作 VM、旁观 VM、专属交换机和登记均清空，登记双副本一致，管理目录为空，临时卷已卸载并删除。Pro 保持运行、网卡断开，合成自动登录关闭；物理宿主启动时间及 `main` 引用不变，没有访问 AI 或外部翻译网站。

206 项 Windows 自动测试、类型检查和构建通过。未签名 preview.7 包审计 5635 个文件、逐一比对 167 个程序文件，未发现本机路径或私有运行资料。汇总器绑定 Pro 实际使用的 7 个程序/资源文件、当前源码与成品包，并单独保留失败对照和只读持久化核验。

忽略文件 `.mu-data/windows-run/pro-volume-complete.json` 保存私有汇总。诊断磁盘副本只用于合成夹具，不代表已经实现产品加密备份功能；账号、SID、个人路径、密钥、磁盘和日志不提交。只读检查使用 [Dissect 的 VHDX 解析器](https://docs.dissect.tools/en/latest/api/dissect/hypervisor/disk/vhdx/index.html)，不挂载或修复原文件系统。

本轮不等同于物理断电、真实休眠/唤醒或物理网络切换验收。长时负载、更多卷挂载组合、VMMS/网络变化与资源压力叠加、已有损坏盘修复及跨所有者迁移继续保留在待办中。
