# Windows 交互安装与 Pro 测试介质

## 已完成的可见向导检查

当前未签名 Windows 预览包使用 Computer Use 驱动真实 NSIS 窗口，不使用静默安装替代这些页面：

- 当前用户为默认选项，所有用户安装入口禁用。
- 在目录页选择独立目录后取消；程序未安装，登记及原数据未改变。
- 选择包含中文、空格、单引号和美元符号的目录，安装完成；生成的实际目录、登记版本与程序载荷一致。
- 完成页不自动打开程序。
- 合成的管理 Node 仍运行时，向导显示关闭程序的提示；原进程未被安装器终止，原程序和数据保留。
- 关闭该合成进程后，从可见向导修复同一目录；完成后程序摘要、原数据和登记保持一致，事务备份正常清理。

只读检查驱动为 scripts/windows-installer-ui-lab.ts。实际窗口、可见控件和阶段记录保存在本机忽略目录；不提交用户名、个人路径、截图或安装登记。该驱动的完成条件要求控制面板可见及 GUI 卸载确认/完成的观察记录，静默清理不能充当 GUI 卸载通过。

## 尚未通过的控制面板与卸载检查

本轮物理宿主的“程序和功能”没有在筛选后显示预览条目，但当前用户的安装登记、程序及卸载器文件确实存在。已核对同一用户、登记字段与文件路径，尚未确定原因；需在全新 Pro 环境交叉复现，不能仅凭注册表记录判定控制面板可用。

Computer Use 在启动卸载器时返回“product policy blocks this app”。本轮没有通过其他 UI 通道绕过该限制。已使用单独的、固定测试目录内的静默卸载完成清理，确认程序和登记消失、独立原数据保留；因此 GUI 卸载及其取消流程仍未验收。

## Windows 11 Pro 介质准备

通过[微软官方 Windows 11 下载与校验页](https://www.microsoft.com/en-us/software-download/windows11)选择 x64 多版本、简体中文 ISO，并取得页面给出的 SHA-256：

    b795b52d598bf8fdea5975844731f4a50c5713876cefc513884354272b023af0

实际下载完成并通过整体摘要校验。scripts/windows-pro-download.ts 固定该版本、语言、官方主机及摘要；临时签名链接只保存在忽略的请求文件中。scripts/windows-pro-inspect.ts 仅以普通用户读取已提取 WIM 的有界 XML 元数据，格式参考 [wimlib 的原始头定义](https://github.com/ebiggers/wimlib/blob/master/include/wimlib/header.h)。本机忽略回执记录 ISO/WIM/XML 摘要和全部镜像索引。

离线元数据确认 Professional 位于索引 4，为 Windows 11 Pro、AMD64、zh-CN、构建 26300.9457。此阶段没有创建或启动 Pro 虚拟机，不代表 Pro 上的组件安装、嵌套 Linux 或网络防护已经通过。

物理宿主不重启，现有评估 VM 不变，不访问 AI 网站。下一步在独立 Pro 测试 VM 部署该镜像，再交叉核对组件准备、嵌套启动和控制面板登记。
