# Windows 安装中断恢复

Windows 安装器在调用旧卸载器之前，为已验证的旧程序建立同卷兄弟目录副本。备份涵盖整个程序目录，逐文件 SHA-256 和目录清单一致后才允许替换；改装至另一目录时，分别保留所选目录和已登记目录。凭据、SQLite 配置、VM 磁盘和运行数据使用独立目录，不进入安装事务。

事务记录通过临时文件、强制刷新和原子替换更新。它记录当前用户、安装进程及启动时间、备份摘要和两个应用专用注册表键的原值。独立的当前用户注册表定位信息不会被旧卸载器删除，所以重试时不提供 /D 也能找到原来的中断目录。

## 重试行为

- **复制尚未完成**：保留摘要一致的旧程序；未完成副本移到单独的保留目录。
- **旧程序已被删除或新程序解压未完成**：先校验全部必需副本，再保留未完成文件、恢复旧程序和原登记，之后执行正常版本检查和升级。
- **新程序已完成登记**：先写入提交状态，再清理已校验的旧副本。提交后清理中断，重试继续清理，不回退已完成的新版本。
- **内容不明**：损坏记录、错误所有者、重解析点、嵌套目录、活动安装进程、运行中的程序或备份摘要不一致，均拒绝猜测性覆盖。原件和副本保留，重试不能绕过版本检查。

副本使用 .mu-backup-随机标识；未完成内容使用 .mu-incomplete-随机标识。两者均位于对应程序目录的同卷兄弟位置。未完成文件不会自动递归删除；只有摘要完全匹配的备份允许清理。若清理已经部分执行，剩余内容单独保留。

安装及恢复均以当前用户执行，不修改系统执行策略，不终止应用或管理进程。应用关闭后重试同一安装器；若仍无法核验，保留这些目录供人工审阅。不要通过删除备份或事务记录来强行继续。

## 验证范围

恢复自动测试直接调用实际 PowerShell 载荷，覆盖原文件/登记恢复、活动安装器及备份写入进程拒绝、损坏副本拒绝、复制中断、新装中断、两个目录的恢复、提交条件、提交后清理中断、链接和所有者拒绝，以及嵌套目录拒绝。

Windows 自动测试 149 项通过，其中包含 10 项安装恢复测试；实际安装进程中断演练包含 5 项检查。应用构建和最终包核验分别执行，程序载荷、内嵌脚本及生成的安装模板与当前源文件一致，包内没有运行数据。当前产物仍是未签名 Windows 预览包。

同一最终安装包另通过 6 项正常安装/重装/卸载检查和 12 项安装后桌面检查，包括运行中拒绝覆盖、原数据保留、组件准备恢复、电源/资源状态、恢复模式往返及确认关闭。最终测试应用已卸载、安装登记为空；物理宿主启动时间和 Mac main 引用保持不变。

实际 NSIS 静默演练使用未占用的应用安装身份与忽略目录，观察真实解压/旧目录删除后，仅终止测试安装器及其子进程。分别验证首次安装和从真实 0.4.65 包升级的中断，随后不传目录参数进行静默重试。原程序的合成 DPAPI/SQLite 配置和用户文件在安装过程中保持字节一致，新包仍能解密旧包保存的配置；最后卸载保留原数据。回执保存在本机忽略文件 .mu-data/windows-run/installer-interruption-lab.json 指向的位置，不提交日志和用户目录。

这验证的是安装进程中断及静默重试，不代表交互式向导、不同登录会话的并行安装、真实突然断电、磁盘硬件故障或全部历史版本均已验收。物理宿主不重启，不进行睡眠、网络切换或 AI 网站测试；Mac 的安装器和发布流程不接入此事务。
