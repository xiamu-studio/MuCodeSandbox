# Windows 受保护登记恢复

2026-10-21，Windows 分支增加登记双副本与旧数据保留规则。Mac 的后端、桌面入口和发布流程不变。

## 产品行为

- 每次登记更新都写入管理员保护目录中的 `vms.backup.json` 与 `vms.json`。格式含版本、当前用户 SID、递增代次和分配记录；先刷新临时文件，再发布副本，两个写入完成后才继续 VM 操作。
- 读取前核验文件类型、硬链接数量、权限和所有者；记录必须符合当前 SID、固定镜像路径、资源范围、VM 身份及构建器权限规则。
- 主副本丢失或发生 JSON/UTF-8 损坏时，使用可核验副本恢复。损坏原件保留为 `vms.rejected-*.json`；写入中断留下不同代次时使用较新副本。同代次内容冲突、权限或身份异常会拒绝继续。
- 旧格式的可信登记自动迁移。存在有效登记时，未登记的数据仍保留，已登记环境可以继续管理；系统页显示保留项数量。新建请求不能占用或覆盖已有未登记目录。
- 两份登记均丢失且 VM 存储仍在时，代理拒绝创建空登记库并拒绝提供运行权限，保留资源供显式恢复。空白存储可以正常初始化。

文件刷新与替换分别使用 [FileStream.Flush(true)](https://learn.microsoft.com/en-us/dotnet/api/system.io.filestream.flush) 和 [File.Replace](https://learn.microsoft.com/en-us/dotnet/api/system.io.file.replace)。这些文件保存管理登记；虚拟磁盘备份、物理断电测试和加密备份仍是独立待办。

## 真实虚拟机验收

在网卡未连接外部交换机的 Windows 11 IoT LTSC 评估 VM 中，以合成普通用户和另一合成管理员完成 18 项检查：

| 阶段 | 实际操作和结果 | 检查数 |
| --- | --- | --- |
| 原盘准备 | 创建真实嵌套 Linux，以 dev 写入随机测试文件，确认停止，仅移除普通用户侧运行清单 | 3 |
| 主登记丢失 | 独立管理员移走主登记；新代理恢复副本及原 GUID，启动前确认磁盘摘要不变，Linux 启动后读回原文件 | 4 |
| 主登记损坏 | 保留原登记并写入截断 JSON；确认生产代理保留损坏原件、恢复一致副本及原磁盘文件 | 4 |
| 两份均丢失 | 移走两个副本；确认生产代理以预期错误退出、没有管理管道、没有新空库，原停止 VM 和磁盘不变 | 1 |
| 显式恢复与清理 | 管理员恢复原登记，再次读回原 Linux 文件；拒绝新建流程占用合成未登记目录，随后清理已停止的测试 VM | 6 |

同一轮另保留一个未登记目录中的独立测试文件，确认没有被自动接管、覆盖或删除。独立管理员最终确认登记副本一致且无分配记录、嵌套 VM 为零；只清理本轮明确创建的未登记测试目录。临时合成自动登录已关闭，外层评估 VM 最终确认为 Off。

当前实现与回执中的原生代码、构建器、客户端和管理模块摘要一致。物理宿主启动标记及 Mac main 引用未改变；没有访问 AI 网站或使用真实账号。

## 回归与边界

Windows 自动测试 95 项通过，其中 11 项直接运行登记存储代码，覆盖空白初始化、旧格式迁移、未登记数据保留、单副本丢失、截断 JSON/非法 UTF-8、两副本之间的写入中断、同代次冲突、双丢失拒绝、非法权限字段、硬链接/目录联接及文件信任拒绝。

未签名安装包完成安装、重装、忙碌拒绝、卸载保留数据和组件准备恢复回归。另完成 5 项包内界面检查，包含系统页实际显示未登记数据数量，以及恢复、取消、发布和正常关闭流程。兼容实测发现的旧未登记资源保留在本机，具体清单不提交。

本机忽略文件 `.mu-data/windows-run/clean-host-ledger-complete.json` 指向完整私有回执；`windows-ledger-audit.ts` 提供当前用户受保护登记的只读诊断，不调用登记修复或 VM 操作。
