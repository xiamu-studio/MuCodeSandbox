# Windows 运行中删除旧快照

2026-10-25 后台源码进展。单独的 `enableLiveSnapshotDeletionPreview` 开关默认关闭；安装版仍为 preview.32，候选安装器仍为 preview.44。本轮不启动桌面、请求管理员权限或运行真实 Hyper-V 操作。

## 行为

Mac 快照页允许删除旧副本而保留当前会话。Windows 同样只删除已确认的独立完整副本；创建和恢复仍要求停止环境。删除时保留原防护会话、浏览器画面、终端连接及待粘贴文字，配置修改、重启、扩容和其他快照操作继续互斥。确认窗口仍要求完整环境名称，输入法选字期间不提交。

普通停止、网络防护失败、宿主资源或电源异常会取消运行中删除。停止不等待旧副本散列或供应程序查询；取消后的结果不把已经停止或出错的环境改回运行。副本删除完成后再次核验原防护会话，才显示保持运行的成功结果，不将当前环境错误描述为停止。若原生恢复状态不能核验，原会话会关闭并保留恢复围栏。

## 原生边界

`SnapshotLiveDeletion` 在短暂的环境锁内捕获原登记对象、完整值快照及任务取消源。文件散列和依赖清点在环境锁与导入锁之外执行；同环境普通写入和需要独占快照文件锁的目录读取会立即拒绝。状态、规则检查、管理通道和停止保持可用。目录轮询遇到产品已知的活动任务时保留当前列表，完成后重新读取。

运行中删除使用单独的删除存储入口，不能创建或恢复快照，也不能申请磁盘空间；不会打开当前磁盘或管理种子内容。继续使用原分配目录固定路径、目录句柄、管理员文件权限、单硬链接受保护读取，以及既有完整副本删除协议。删除意图先持久化，再将原副本改名为 `delete-active-<id>`；每个文件的身份、大小及散列都必须符合原凭据。只移除已登记的磁盘、种子、清单和空目录，未知内容继续保留。

每个删除阶段前检查原登记对象及值、备份/恢复/扩容围栏、取消和宿主状态。`review-snapshot-delete` 只读取 Hyper-V/存储供应程序，允许明确的 Running 或 Off，拒绝过渡状态，并复核原 VM 标识、资源、私有交换机、网卡 ACL、固定 MAC 和管理 ISO。

候选位置仅由规范快照 ID 和受保护分配目录推导，同时覆盖发布目录及退休目录的 VHDX/ISO。扫描所有 VM 与检查点的硬盘和 DVD、逐级父磁盘和宿主已挂载映像；发现引用、挂载、差分副本、重解析路径、远程依赖、环路、数量/深度超限或供应程序失败均拒绝。没有成功读到供应程序状态时，不将其视为无引用。历史快照资源可以不同于当前 VM，删除权限仍绑定所有者、环境及原平台标识。

停止状态下的旧删除入口保持原停机核验和资源压力下回收空间的能力；运行中删除不享有该例外。部分删除取消后保留原意图，可以在已确认停止后明确接续。没有增加自动扫描或认领旧目录的清理逻辑。

## 验证范围与剩余验收

普通用户临时文件及线程测试编译实际生产的运行中删除方法和完整磁盘事务核心；Hyper-V、ACL、受保护登记及供应程序边界使用合成适配器。另以生产 PowerShell 函数 AST 配合临时普通文件和供应程序替身检查依赖边界；完整生产代理编译后的反射测试核对实际准入方法。认证 HTTP 测试只接受服务器选择运行模式，拒绝客户端追加权限字段。

快照页面分别使用生产 React 和实际 development StrictMode；构建工作区使用真实本机 WebSocket 终端及最小 RFB 接收端，核对任务期间同一终端/画面节点、连接、草稿、继续输入、出口/防护读数及独立停止。合成 RFB 画面不代表真实 Linux 渲染或输入法实机验收。

最终结果、冻结输入、原生摘要、编译副本和清理凭据记录在当前 Codex 工作区 `outputs/snapshot-live-deletion-evidence.json`。真实管理员入口、保护目录权限、运行中 Hyper-V 引用变化、盘符/文件占用、实体电源故障及安装版交互仍待实测；不能凭本轮替代这些验收。
