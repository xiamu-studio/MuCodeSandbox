每环境独立 Hyper-V VM、专属 **Private** 交换机和双向拒绝全部 IP 的网卡 ACL。不创建宿主虚拟网卡、NAT、ICS、物理桥接或自动开机。

管理通路为：Windows 控制器 → 每控制器独占的 127.0.0.1 临时端口 → 原生 AF_HYPERV 客户端 → 指定 VM GUID 的 Linux AF_VSOCK → 客体回环 SSH。SSH 私钥、固定 HostKeyAlias 和独立主机密钥负责认证；原生助手只接受明确 VM GUID，不接受通配 VM。没有宿主 shell、文件服务或普通 IP 后备通道。控制器退出时助手关闭全部连接。

业务流量在 Linux 内经过 nftables、sing-box TUN、受控 DoH 和 45 秒内核联网许可，再通过 SSH 反向转发到唯一配置的上游。网络与探测身份为专用 UID 970/971；安装规则前核验实际身份。业务 UDP/IPv6 不放行，没有直连后备路径。

生产启动先检查关闭的客体防护，再建立转发。至少两个不同接收端的有效回执一致且符合批准出口，才开放业务许可。持续检查内核规则、文件权限、路由、DNS、宿主网络和许可。异常分别尝试断开通道、撤销许可和关闭 VM；停机确认独立于 ACL 完整性。

45 秒许可存在时间窗口，不承诺瞬时断网、抵抗客体 root 完全失陷、隐藏虚拟化或保证账号不被关联。

### Windows 系统组件

系统准备只接受固定的 Hyper-V、OpenSSH 客户端和 Hyper-V 管理服务操作，不接受组件名、命令或任意输出路径；不会安装 SSH 服务端或改变入站 SSH 规则。软件不修改 UEFI/BIOS，不为不支持 Hyper-V 的 Windows 版本解锁组件。系统页显示实际检测值，无法确认硬件条件或有待重启状态时不允许继续。

Windows 组件安装由独立的受保护进程完成，关闭桌面或权限代理不会强制终止正在进行的系统维护。任务记录与进程创建时间用于重新读取结果，正在执行的系统维护不提供取消按钮。完成后如 Windows 要求重启，用户保存工作后自行重启；仅系统准备会话即使组件已就绪，也须重新打开软件才能获得 VM 管理权限。

使用 Windows 内置的 [Enable-WindowsOptionalFeature](https://learn.microsoft.com/en-us/powershell/module/dism/enable-windowsoptionalfeature) 和 [Add-WindowsCapability](https://learn.microsoft.com/en-us/powershell/module/dism/add-windowscapability)，均指定不自动重启。硬件条件参照 [Microsoft Hyper-V 要求](https://learn.microsoft.com/en-us/windows-server/virtualization/hyper-v/host-hardware-requirements)。受保护的固定脚本由已核验的组件读取执行，不修改系统的 PowerShell 执行策略。

每完成一个组件操作便持久化更改和重启要求；后续 OpenSSH 安装失败不会抹去已完成的 Hyper-V 记录。失败时重新查询实际状态，查询也失败则保留已有回执和原始错误。隔离故障测试覆盖这两条失败路径。当前 82 项 Windows 自动测试通过；另已完成隔离评估 VM 的缺失 Hyper-V 安装、仅测试 VM 重启与嵌套 Linux 的 3+5 项检查，详见 [全新 Windows 验收](windows-clean-host-validation.md)。

普通用户侧的原生组件编译、种子镜像生成、管理文件清理与安装启动器，同样读取应用内固定脚本后执行命令，不依赖用户放宽 PowerShell 文件执行策略。子进程 `Restricted` 策略测试覆盖中文/单引号路径、实际代理与通道编译、ISO 生成和清理边界；安装启动器另检查 Windows 命令行长度限制，测试不执行真实提权。机器与用户执行策略保持原样。真实普通用户 VM 回归 7 项及安装后的准备恢复/取消 4 项通过；VM 回归结束后删除本轮合成环境，保留报告。

### 创建恢复与删除

磁盘导入前先保存受保护的分配记录，源文件读取失败和取消操作也保留可检查、可删除的记录。启动恢复会实际查询 Hyper-V 并确认停机，查询失败不会解释为资源不存在。对从未完成创建的环境，重新启动可以清理未完成的分配并重试；曾经完成创建的环境只恢复原 VM GUID 和运行清单，不重建原磁盘。管理密钥缺失、身份/磁盘路径改变或已存在环境防护异常时保留数据并报错。
