# Pro 上的实际预览包安装与重装

2026-10-22，在已独立部署的简体中文 Windows 11 Pro 26300.9457 测试 VM 中，以合成普通用户运行实际 NSIS 预览安装包。网卡始终断开，没有 AI 网站或真实账号测试。

## 已通过的范围

使用实际 Windows 预览版 0.4.66-preview.1，在含中文、空格、单引号和美元符号的独立目录中执行：

| 阶段 | 已验证行为 | 检查数 |
| --- | --- | --- |
| 安装 | 普通用户实际安装、版本及登记一致；安装包自带 Node 创建并解密独立 DPAPI/SQLite 原配置；系统“程序和功能”项目列表包含该安装 | 3 |
| 重装 | 安装目录内的管理 Node 运行时拒绝替换且不终止进程，程序和数据摘要不变；关闭合成进程后同版修复，原加密配置仍可解密；系统项目仍存在 | 3 |

原配置、合成用户文件和应用目录分开保存。验证安装动作前后的字节摘要；正常打开数据库引起的合法写入，在下一次检查前重新建立基线。

系统列表通过 Windows Shell 的“程序和功能”名称空间读取，不以注册表存在代替系统列举结果，格式参考 [Microsoft 的说明](https://devblogs.microsoft.com/oldnewthing/20131230-00/?p=2233)。在本机 Windows 版本中，直接 GUID 字符串返回空对象，使用 shell::: 前缀后可以读取；回归执行实际只读枚举。之前未开始安装的查询失败保留在历史记录，只有确认没有活动客户端、实际安装和原数据时才允许重试。PID 已被无关进程重用不被误认为原客户端仍运行。

中文 JSON 回执统一按 UTF-8 读取，避免 Windows PowerShell 默认文本编码把实际正确的中文路径记成乱码。NSIS 最后一个目录参数通过无 shell 的原始参数传递，特殊字符作为路径数据处理。

Windows 自动测试 158 项通过，新增系统名称空间枚举和失败后重试边界检查。实际安装及修复私有回执由本机忽略文件 .mu-data/windows-run/pro-package-complete.json 汇总；不提交账号、SID、个人路径、原配置、截图或日志。

## 保留环境与人工步骤

应用和原加密数据仍保留在该测试 VM 中。独立收尾确认没有安装进程或内层 VM 仍运行，停用合成自动登录并将 Pro VM 关闭；物理宿主没有重启，Mac main 引用保持不变。

真实桌面主入口的首次管理员认证尚未完成，没有代填、取消或确认 Windows 认证对话框。只有人已准备好时才提供 package-open-main --human-ready 诊断入口；它启动实际安装程序并打开该测试 VM 的连接窗口，记录的只是启动请求，不充当桌面就绪或 UAC 通过。

本轮没有执行 GUI 卸载或其取消流程，也没有把已有静默清理证据算作 GUI 验收。此前物理宿主界面筛选未显示条目的状态未在本轮重新验收；Pro 中的系统名称空间已实际列出正确程序。
