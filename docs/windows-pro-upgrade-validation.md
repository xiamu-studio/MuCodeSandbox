# Pro 实际预览版升级与原盘读回

2026-10-22，在网卡断开的简体中文 Windows 11 Pro 测试 VM 中，使用两个已经构建并审计的真实安装包，完成 `0.4.66-preview.5 → 0.4.66-preview.6` 升级。没有改写安装包版本来代替历史版本，也没有访问 AI 或外部翻译网站。

## 已通过的范围

新建独立的合成普通用户，保留原测试用户的安装、程序登记和 DPAPI/SQLite 配置。新账号实际加载自己的用户配置，验证 HKCU 隔离及 CurrentUser DPAPI 读回。自动测试使用临时的非交互窗口站，不操作已有桌面或 Windows 认证界面。

| 阶段 | 实际验证 | 客户端检查数 |
| --- | --- | --- |
| 旧版安装 | 真实 preview.5 NSIS、普通用户、中文/空格/单引号/美元符号目录，版本登记一致 | 1 |

共 15 项客户端检查通过。安装、修复、降级拒绝及卸载前后，独立管理员分别核验停止 VM 的 GUID、磁盘标识、附着路径、容量和整份 VHDX 的 SHA-256；这些安装动作没有改变原盘字节。原管理文件摘要也保留。正常打开数据库或启动客体产生的合法写入，在下一阶段前重新建立基线。

旧版和新版分别使用源码摘要匹配的受保护权限代理，测试期间不替换现有默认代理指针。最终将保留后端的 10 个程序文件与当前安装包逐个绑定，核对两份实际安装器的已审计摘要。

## 夹具权限问题及处理

第一次卸载后读回已经成功，但删除阶段被管理目录句柄检查拒绝。以新账号真实令牌执行只读核验，六个祖先/运行目录中只有夹具公共父目录返回 Win32 `ERROR_ACCESS_DENIED`：它原本仅授权原测试用户。

确认原控制器和代理已退出、原 VM 停止且原盘/登记仍在后，保留失败回执，给新账号增加该父目录本身的列举和属性读取权限，不向子目录继承。修复夹具前后原盘和加密文件不变；因已确认关闭的后端正常操作而变化的 SQLite 单独重新建立基线。六个目录实际句柄检查全部通过后，重新完成卸载后读回及删除。

没有修改产品删除器或放宽重解析点、原目录句柄、已登记资源边界。独立收尾恢复父目录的原 DACL，并校验失败历史仍在。后续新夹具初始化也记录这项临时权限，以便收尾恢复。

## 收尾及证据

- 独立检查全部受保护用户登记：双副本一致，登记、VM、专属交换机和受保护 VM 目录均为空；本次客户端、权限代理和通道助手无残留。
- 原测试用户的应用字节、程序登记和合成原配置保持完整，默认代理指针未变化，VMMS 正常。
- 外层 Pro VM 保持运行、网卡断开、合成自动登录关闭，保留后续人工桌面验收；物理宿主启动时间及 Mac `main` 引用不变。
- 类型检查通过；安装、版本、恢复和 Pro 保护相关的 22 项自动回归通过。

本机忽略文件 `.mu-data/windows-run/pro-upgrade-complete.json` 汇总实际阶段、独立收尾、安装包摘要和代码绑定；账号、密码、SID、个人路径、原配置、磁盘和日志不提交。

诊断入口为 `scripts/windows-pro-upgrade.ts`、`scripts/windows-pro-probe.ts upgrade-*` 和 `scripts/windows-pro-upgrade-evidence.ts`。已有阶段必须先检查实际进程和回执；观察超时不构成重跑依据。失败后的本次夹具修复仅接受已确认退出的特定权限错误，不重置账号密码或丢弃旧失败记录。

本轮使用静默安装链路。完整 GUI/UAC、真实输入法、GUI 卸载/取消、实际断电及更多历史格式/跨用户迁移继续单独验收；本轮结果不代替这些项目。
