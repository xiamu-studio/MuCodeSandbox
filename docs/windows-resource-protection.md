# Windows 容量准入与资源临界保护

2026-10-21，Windows 受保护后端增加动态磁盘增长预留、启动内存准入和独立资源保护线程。Mac 的后端与启动/发布流程保持独立。

## 准入与运行规则

- 每个用户的已登记虚拟磁盘总容量上限为 1 TiB，包含未完成分配；单环境及分配数量继续使用现有范围。超限拒绝发生在新登记提交前，已有环境仍可核验、停止和删除。
- 创建、重建与封存使用跨进程导入锁，磁盘转换完成后才释放。按实际卷标识汇总本机当前 VM 的可写磁盘，以及受保护目录中尚未绑定 VM 的磁盘；容量加上 1% 或 64 MiB 的格式/配置余量（取较大值），减去实际占用字节计算剩余增长需求，再计入本次磁盘、缓存复制和必要的源盘物化。
- 磁盘可用空间使用目录所在实际卷的 `GetDiskFreeSpaceEx`，稀疏/压缩文件占用使用 `GetCompressedFileSize`。本地重解析点和无法确认的磁盘会拒绝准入；远程卷不作为本地空间读取。
- 启动通过进程内及跨进程互斥，重新核对磁盘预留、当前物理可用内存和已分配的 Hyper-V 内存。环境配置不得超过物理内存的 80%；每次启动为宿主留下至少 1 GiB 或物理内存的 10%，取较大值。
- 独立原生线程每 2 秒核验实际资源底线：磁盘 2 GiB，物理内存至少 512 MiB 或总量的 5%，取较大值。临界或指标不可核验时，撤销管理/转发连接，取消增长及启动操作，核验并关闭当前用户登记的 VM。
- 停止、状态查询、删除和可安全执行的缓存清理不受增长操作的取消令牌阻断。旧会话在压力解除后继续拒绝启动；新会话重新核验。资源关闭结果与“停机尚未确认”分别呈现。
- 系统页显示实际内存、启动预留、磁盘底线和用户虚拟容量。控制器监测到原生资源关闭时撤销终端/浏览器等访问，资源故障不作为网络变化显示。

卷、内存指标分别参考 [GetDiskFreeSpaceEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw)、[GetCompressedFileSize](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getcompressedfilesizew) 和 [GlobalMemoryStatusEx](https://learn.microsoft.com/en-us/windows/win32/api/sysinfoapi/nf-sysinfoapi-globalmemorystatusex)。外部程序仍可改变资源使用量，因此每次准入重新取值，运行中继续保留临界保护。

## 真实隔离 Windows 验收

专用评估 Windows 的独立 VHDX 仅在 Off 状态从 96 GiB 扩展到 160 GiB，并在客体扩展 C 分区。宿主先核验剩余空间，物理宿主磁盘和分区不参与调整。外层 VM 保持静态 10 GiB 内存和断开的网卡，压力负载只在该客体中运行。

| 阶段 | 结果 | 检查数 |
| --- | --- | --- |
| 创建与启动 | 两个真实 Linux 盘；拒绝阈值覆盖、超大磁盘、超物理内存配置；独立进程启动锁与两个 6 GiB VM 启动竞争；释放内存后依次启动并写入独立 canary | 8 |
| 实际低磁盘空间 | 客体卷降至低于 2 GiB，原生保护确认两个 VM Off、拒绝旧会话重启；释放合成文件后旧会话继续关闭 | 4 |
| 实际临界内存 | 有界驻留负载触发生产内存底线，原生保护确认停止；释放负载后保持旧授权关闭 | 4 |
| 新会话恢复 | 原 GUID 与原盘文件均读回；实际登记到 1 TiB 后拒绝额外预留；清理两个 VM 和失败分配 | 4 |

共 20 项通过。内存负载仅增加测试进程自身的工作集并锁定有界页面，最多 4 GiB，所有路径均解锁/释放；没有修改生产阈值、系统用户权限或宿主资源。普通可分页负载未达到临界值的失败记录留在本机，没有作为通过证据。

Windows 自动测试 119 项通过，包括精确容量/内存边界、溢出拒绝、实时 Win32 指标、控制器资源关闭传播，以及登记代次耗尽时保留两份有效原件。更新后的未签名安装包另完成安装、重装、忙碌拒绝及卸载保留数据回归，系统页实际资源统计与组件准备流程也通过验收。

独立管理员确认压力负载释放、登记清理、嵌套 VM 为零，禁用合成自动登录后确认外层 VM Off。回执中的原生代码与管理模块摘要对应当前实现。本机忽略文件 `.mu-data/windows-run/clean-host-resources-complete.json` 指向私有证据；硬件统计、进程标识、账号和磁盘不提交。物理宿主启动时间、Mac main 引用未变，没有访问 AI 网站；Linux 业务联网许可在压力实验中保持关闭。

## 后续覆盖

后续 preview.7 已补上真实双卷、活动新旧业务流与磁盘压力，修复首次初始化未落盘时强制停机导致管理身份损坏的问题，并通过原盘恢复，详见 [启动持久化与多卷压力](windows-guest-durability-validation.md)。Windows 原盘扩容另见 [磁盘扩容验收](windows-disk-growth-validation.md)。

实际 VMMS 不可用与低磁盘压力同时存在、先释放压力再恢复管理服务的行为，已另完成 9 项 [叠加故障验收](windows-compound-fault-validation.md)，包括原工作进程存活时的新旧业务关闭、旧授权拒绝及新控制器原盘恢复。

更多卷挂载路径组合、长时负载、网络变化与压力叠加，以及管理服务、内存或磁盘故障的其他组合仍保留在完整回归中。快照、加密备份、旧管理员环境迁移和更广泛的旧资源接管继续单独实现；当前用户完整受保护 VM 已新增 [显式登记恢复](windows-explicit-recovery.md)。本轮评估 Windows 盘扩展属于压力夹具准备。
