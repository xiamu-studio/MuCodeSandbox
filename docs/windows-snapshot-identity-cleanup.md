# Windows 快照身份临时资料清理

## preview.45 快照身份临时资料的持久清理（后台源码，未安装）

快照保存配置、恢复及重放会用原管理密钥执行ssh-keygen一致性检查。此前这些校验沿用无持久归属清单的临时目录，正常结束递归删除；清理失败还可能覆盖原始错误。本轮将captureState和validateSeed（含files调用）接入既有WindowsBackupCleanupRegistry：只在新建且空的私有目录登记windows-snapshot-identity-work，先持久保存原目录及Store祖先、PID/创建时间和原文件身份，再通过受控writer写management-check或host-check。该用途拒绝磁盘、seed、环境子目录及额外路径。

索引仍使用既有SQLite、AES-GCM及Windows实际入口的当前用户DPAPI密钥。封口只能来自本次producer记录的文件身份/大小/时间/摘要；未知新增、替换、硬链接、ADS、祖先变化、坏索引或未封口记录保留，不现场重新采集为删除授权。实际清理继续使用原生句柄核验、逐文件和空目录删除。来源用途扩大到快照校验，两份原生实现及路径范围没有改动；旧同前缀目录从不自动认领。

清理和业务结果分开：原校验错误或取消不会被二次清理异常覆盖；原校验成功但清理未确认时不会返回成功。创建和恢复在首次身份采集失败时不进入native create/prepare/commit。已经提交的原生快照仍按原事务决定接续，不能因为临时资料告警重做准备或提交；补充检查确认prepare/commit/ack均一次、已提交结果保持，未知文件及独立告警继续保留。

快照产品状态只读筛出本用途的告警，并提供独立索引错误；无需运行组件，也不把临时清理问题伪装成磁盘事务pending。目录读取失败仍保留已核验的本地告警、显示读取失败并禁用写入，不显示“暂无快照”。页面按钮打开现有备份/恢复窗口的清理记录，不自动清理或重复恢复。坏索引限制创建/恢复；已提交删除事务的续清理不受这一无关限制。
