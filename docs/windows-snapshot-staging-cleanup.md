# Windows 未发布副本的原始凭据与清理

本阶段在“显示遗留条目、拒绝追加复制”的基础上，接入新副本的清理流程：创建时记录原始文件身份，停止环境后核验，输入环境全名确认，按固定句柄删除；中断后接续原记录。仅有 `create-next-*`、`restore-next-*` 名字的旧文件不具备清理授权，不补造凭据。

这是后台源码与本机合成验证阶段。实际安装版仍为 preview.32，保留的候选为 preview.44；没有运行新安装器、应用窗口、UAC、真实 VM 或 Hyper-V 管理命令。新清理沿用默认关闭的快照预览开关；已经开始的受保护清理记录可在新操作关闭时接续。加密备份恢复为独立可启动 VM 并读回新旧数据的实机闭环仍待验收。

## 原始对象记录

`MuOfflineSnapshotStore` 的复制和首次元数据写入接入 `IStagingFactory`，生产代理使用 `MuSnapshotStaging`。它在固定父目录句柄下独占创建目录及三个固定角色的文件，记录卷/文件 ID、创建时间、环境、VM/所有者绑定和根目录身份。受保护的追加帧有长度、校验和、顺序与总量限制，不保存明文管理密钥、密码或配置。

新对象在创建时即设为退出删除。对应身份帧 `Flush(true)` 后，才清除退出删除状态并交付复制循环。进程在记录落盘前退出时，内核关闭原句柄，尚未获准保留的新对象随之移除；记录落盘后退出，则可以核对实际剩余原对象。创建描述符显式设置管理员/SYSTEM 所有者及 ACL，不依赖令牌的默认对象所有者。

清除创建时的 on-close 状态使用扩展 `FILE_DISPOSITION_ON_CLOSE`。普通删除信息的 false 值不能取消创建时的退出删除标志；验证曾发现元数据关闭后消失，改用扩展状态后，成功发布和真实进程退出边界均已复核。[微软的扩展删除状态说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/ns-ntddk-_file_disposition_information_ex)描述了该状态。

发布通过原目录句柄、固定父目录和不可覆盖的相对名称重命名，再登记发布。凭据在快照目录之外，正式快照仍保留原来的磁盘、seed 和 manifest 三项。发布后即使回执丢失，也不能据旧前缀清理正式快照、`restore-active` 或已确认的回滚历史。

## 核验与确认

“核验清理”先创建只读任务。代理核对完整环境归属、已停止状态、受保护凭据和根目录身份，逐项固定原始目录及文件；替换、硬链接、重解析点、额外文件/子目录和数据流均拒绝。核验使用原对象身份、当前长度和修改时间，不把未完成的 VHDX 当成完整镜像，也不把清理核验当作备份内容完整性证明。

固定文件句柄期间，生产 PowerShell 核对当前 VM、所有 VM/检查点的磁盘及 ISO 引用、差分父链和宿主挂载。所有查询必须成功，源 VM 仍为 Off；返回的 VM、复制 ID 和资源值须与保护记录一致。部分候选 VHDX 不做格式解析，其安全依据是原始创建凭据、完整引用清单及删除句柄。已发布快照原有的完整 VHDX 校验保持。

核验结果只通过当前任务取得，在应用中短时保存并一次使用。请求不能提供路径、文件身份、密钥或配置。确认需匹配环境、复制 ID、操作类型、令牌、重试方式及完整环境名称；过期、替换、其他任务或取消后的迟到结果不能继续。实际清理会重新固定对象，在每项删除前再次核对清单、依赖及归属。源环境或当前管理资料不完整时，先保留文件并处理恢复问题。

## 中断接续

首次删除前先持久保存原对象的长度、修改时间及身份，之后按固定句柄逐项删除。没有递归删除，也不按名称重新打开后删除。未知新增内容会保留并停止后续处理。

清理中标记独立登记。文件和目录已移除、完成帧尚未归档时，清单仍显示可接续条目。已有计划只接受剩余原对象，重复请求不会重新开始新删除。凭据尾部不完整时，仅在剩余对象仍按完整帧核验、令牌匹配且明确确认后接续；完整帧的校验损坏直接拒绝。

依赖查询不持有 `VmGate` 或 `ImportGate` 等待提供程序。单环境维护锁阻止并发修改；停止、退出和电源撤销可独立取消，迟到结果不能触发删除。源 VM 保持停止时，磁盘资源告警不会取消用于释放空间的清理，显式取消和退出仍有效。这不保证抢占内核 I/O 或外部管理员的全宿主操作，相关实机验收仍待完成。

## 验证边界

普通 Windows 临时文件覆盖真实 NT 创建、退出删除状态、原句柄重命名/删除、未知内容拒绝、接续和进程终止。生产清理方法用明确的 VM/ACL 适配器单独编译，验证停止不等待阻塞查询、记录替换、错误依赖回执及部分删除恢复。完整生产 EXE 另在普通权限下编译、自检，拒绝普通目录/文件与管理入口，并检查创建描述符仅授予管理员和 SYSTEM。

认证 Express、实际 WindowsManager/SQLite、编译后服务及无头 Chrome 分别验证确认、令牌、过期、取消、资源告警和页面交互。它们不等于受保护管理员路径上的真实清理、Hyper-V 引用/挂载、磁盘填满、物理休眠或发行验收。旧的偶发 `create-next` 访问拒绝及输出辅助进程 EBUSY 仍未确认原因，不以本阶段通过结果宣称已修复。
