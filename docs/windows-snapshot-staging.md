创建快照及恢复准备会先向 `create-next-*`、`restore-next-*` 写入完整副本，再发布到正式快照或 `restore-active`。审阅确认：复制取消、写入失败或进程退出发生在发布前时，原实现会保留该目录；普通快照列表不显示它，重试又分配一份复制空间。这是独立的空间累积缺口，不能据此认定上轮 `create-next` 访问拒绝的原因。

源码现在提供当前所有者、固定环境的只读 `snapshot-staging` 请求及认证 HTTP 接口。它仅枚举快照根目录下以这两个前缀命名的条目，不读取配置、遍历子目录、跟随链接或推断可删除归属。大小写差异、非标准后缀、同名前缀的普通文件也会阻止追加复制，最多返回 32 项，并明确是否截断。未知名称的其他数据继续保留。

发现条目时，产品层和原生复制核心都拒绝新建快照及开始新的恢复准备。原生入口在捕获恢复来源、校验快照磁盘及申请复制空间前复核；核心在分配复制容量前再检查。页面显示条目名称和来源阶段，同时暂停这两个按钮。请求绕过页面也不能追加副本。

已发布快照的查看、历史导出、已确认的快照删除记录、已发布恢复事务的回滚与确认继续使用各自原有校验。遗留的未发布副本本身不是恢复事务，不会单独阻止普通环境启动。任务因该前置检查拒绝时显示明确原因；只有重新确认虚拟机为 Off 才保留“已停止”状态，否则显示环境错误，不推断已停机。

本轮没有实现仅凭目录名字的删除，也不把这些条目加入“继续清理”。自动或显式清理还需要在复制前生成持久、受保护的原始归属和文件身份凭据，并按句柄核验已记录对象；没有该凭据的旧条目继续保留。32 项截断也不表示只剩这些数据。当前接口不声称精确占用字节，界面不提供可误删未知目录的按钮。

测试使用普通 Windows 临时文件和合成 VM/空间/保护适配器。覆盖创建和恢复准备的磁盘复制、seed 复制、发布前中断；两个真实子进程分别在磁盘复制时被终止，新进程复核遗留、原文件及零新增复制容量；另覆盖已发布事务接续、已有导出、未知数据、异常名称、32 项上限、认证接口、任务状态和无头页面。它们不等于真实 Hyper-V、受保护管理员路径、磁盘填满或安装版验收。此前单次访问拒绝仍未确立原因。
