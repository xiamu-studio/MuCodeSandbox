## preview.36 产品接入源码

WindowsSnapshotProduct 将原有加密协调器接到管理器任务、启动接续及本地认证 API。启动先核验并接续原生／SQLite 待完成事务，再允许普通恢复；即使新建快照开关关闭，已有事务仍可接续。宿主运行组件尚未激活时不查询原生恢复操作，保留组件准备及重新打开软件的流程。

## 保存方式

Mac 现有 `server/snapshots.ts` 保存停机后的磁盘、环境配置和相关运行资料。Windows 采用同类停机完整复制方式。现有 Windows 分配、备份和扩容要求固定位置的独立动态 VHDX，不能直接启用会改变磁盘链的 Hyper-V 检查点后跳过现有核验。

`native/windows/OfflineSnapshots.cs` 中的 `MuOfflineSnapshotStore` 是本地文件事务核心，现由 `SnapshotOperations.cs` 接入代理。它只接收调用方固定的分配目录、规范环境 ID，以及目录保护、受保护读取、空间准入和停机核验回调。快照 ID 与事务 ID 分别生成；调用方不能从元数据指定磁盘路径。固定磁盘和种子文件与有界配置封套一同保存；封套包含所有者配置密文及由受保护登记生成的原生资源字段，普通调用方不能用配置密文覆盖这些资源字段。

## 恢复提交与接续

1. `PrepareRestore` 完整复制并校验目标快照，核对当前磁盘和种子摘要后，一次发布包含新文件、旧摘要、旧/新配置密文的事务目录。发布前不替换原盘。
2. 分别用文件替换保留原磁盘和原种子；每个替换前仍要求停机和原内容匹配。全部替换完成后记录 `applied`，返回快照配置。此时仍禁止启动。
3. 后续产品协调器必须验证并持久化配置、管理身份资料及原生资源登记，然后按**本次事务 ID**调用 `CommitRestore`。提交前核对新磁盘/种子及保留的原始回滚文件，持久化 `committed`。
4. `RecoverRestore` 遇未提交事务，先核验整套回滚方案，才恢复原磁盘与种子，并返回原配置密文供协调器重放。提交已持久化时核对并保留新版本，重放新配置。损坏或未知内容保留现场并拒绝推断。恢复本身再次中断也可以接续。
5. 协调器完成相应配置重放后，用相同事务 ID 确认。事务目录移动到保留历史，原盘或中间文件不在此步骤删除；空间释放需另有明确产品流程。旧事务请求不能提交或归档后来针对同一快照的新事务。

本核心不处理完整 Hyper-V 配置、所有者 DPAPI、管理密钥、云种子内容语义或磁盘格式。以上均是生产协调器和原生代理接入前必须补齐的检查，不能以回调夹具结果替代。
