## 最初缺口与触发条件（历史）

独立加密备份携带完整环境盘、原 seed 和管理身份。历史记录已验证同机跨普通用户 SID 的无基盘恢复、启动和原数据读回；这些证据只属于当时载荷与范围，不能证明之后两份受保护登记都丢失或损坏时仍能重新登记。

当前缺口同时满足以下条件时出现：

1. 环境由独立备份恢复，目标没有原来源基盘；恢复完成后可以正常使用现存 VM。
2. 管理配置、密钥、受保护 VM、独立磁盘和 seed 仍完整，VM 已停止。
3. 受保护 `vms.json` 和 `vms.backup.json` 都丢失，或两份 JSON 都不可读，需要显式登记恢复。
4. 原生恢复审阅仍要求存在唯一的来源基盘，并核验其 SHA-256；没有该基盘就拒绝审阅。

拒绝发生在恢复登记发布前。当前路径保留 VM、磁盘、seed、管理资料及原登记文件，不会因此重新导入、覆盖、删除或启动 VM。此结论来自代码路径复核，不能当作真实双登记故障验收。

## 现有资料不足以直接替代来源授权

- `backupRestore` journal 只在原生登记内，恢复成功即删除，不能在双登记丢失后提供独立依据。
- 普通用户的管理 manifest、密钥与 DPAPI 绑定可供恢复向导确认原管理资料（`server/platform/windows/recovery-candidates.ts:45–52`），不能直接替代管理员层对受保护资源来源的授权。
- 快照 envelope 包含来源与资源信息，但依赖已有原生登记及平台 ID 核验，而且环境可能没有快照（`native/windows/SnapshotOperations.cs:42–49,107`），不是通用来源凭据。
- 现存磁盘文件名、目录名、VM 标记或现场计算的摘要，都不能单独证明它是此前经受限导入流程接受的原盘。不得扫描现存资源后补造来源凭据。

## 最初建议方案（历史；当前双槽及导入接入见末节）

新增独立于双登记的受保护导入来源回执，例如固定 `UserRoot/restore-origins/<id>.json`。目录和文件仅允许 Admin/SYSTEM 写入，不能放在 VM SID 可写的分配目录中，也不接受调用者指定路径。严格限制格式、字段、大小、记录数量和用途，并保持完整祖先固定与常规文件核验。

建议绑定：格式与用途、目标 owner SID、环境 ID、精确平台 ID、原来源镜像摘要、导入时盘和 seed 的摘要及长度、现存盘与 seed 的卷号/文件 ID/出生时间、资源配置和受保护根身份。回执应在完整复制、精确 VM/策略复核后原子写入并持久刷新，随后才清除恢复 fence；写入失败不得宣称恢复完成。

运行后的环境盘会合法变化，导入时 SHA-256 只能作为来源记录，不能要求当前盘一直等于初始摘要。无基盘恢复审阅应核对有效回执、现存文件身份、当前停止 VM 的精确平台 ID、拓扑、策略、资源和 seed 绑定，并继续使用前后事实、登记指纹及确认计划。缺失、旧版、损坏、已替换或未完成的回执一律保留资源并拒绝自动接管。

原来源基盘存在时的旧恢复路径继续保持。不能通过直接删除来源基盘检查来扩大现存盘接管范围，也不应为了补此缺口强制复制一份大基盘增加磁盘占用。

## 必须补齐的生命周期与故障验收

- **首次导入与中断：** 在复制、VM 创建、最终核验、回执刷新、清除 fence、双登记保存各边界取消或终止进程；丢回包后使用同一档案重试。只允许原身份继续，不覆盖已有目标，不把半完成回执当作授权。
- **双登记故障闭环：** 无来源基盘的真实独立恢复 VM 先启动并写入新数据，再停止；分别测试双缺失、双损坏、单副本损坏。只读审阅与确认登记后，重开控制器并从同一原盘启动读回旧、新数据；保留损坏原件及登记版本/指纹边界。
- **回执与路径信任：** 缺失、截断、错误格式、未知字段、越界、重复或冲突记录、旧 SID、错误环境/平台/根、普通用户或 VM SID 可写 ACL、所有者改变、重解析点、硬链接、文件或目录 ADS、父目录替换、文件 ID/出生时间变化均拒绝；不采用未知同名资料。
- **VM 与依赖事实：** 运行中 VM、平台替换、重命名、标记/Private 交换机/ACL/自动启动/资源改变、seed 替换、共享磁盘、父盘或其他 VM/快照依赖、审阅后变化均拒绝。取消和检查失败不得隐式修改或启动 VM。
- **正常运行与扩容：** 正常盘内容增长不误判；合法扩容及其 journal 的各中断点与来源回执一致，不能接受不明容量变化。`native/windows/DiskGrowth.cs:14–21,43–54` 的身份与容量证明需要联动，不能留下旧资源授权。
- **快照替换与回滚：** 完整停机快照恢复会替换盘/seed，资源也可变化。提交、回滚、旧进程退出、新控制器重放以及 acknowledge 前后均需更新或撤销回执；未完成快照 fence 继续阻止普通登记恢复。不能让旧文件 ID 回执授权新盘。参见 `native/windows/SnapshotOperations.cs:86–104`。
- **删除与身份复用：** 只有确认精确 VM、交换机及专属存储已移除后才退休对应回执；删除中断可重试。遗留回执不能授权后来同 ID 或同路径的其他资源，重新导入不得覆盖不明旧凭据。参见 `native/windows/HyperVBroker.cs:228–239`。
- **跨 SID、跨机器及旧版：** 新目标的回执必须由目标受限导入流程产生，不能直接信任复制来的源机/SID 回执；旧版无回执环境保留并提供明确限制，不能现场自动迁移。分别核验目标 DPAPI、来源拒绝访问和目标原盘重开。
- **产品与发布：** 恢复向导如实显示限制、一次性确认和失败原因，成功后需重新打开正常控制器；源码/合成测试、包内验证、真实 VM 故障和桌面交互分别留证，不相互代替。

以上全部仍是待实现或待验收范围；当前桌面操作暂停继续有效。
