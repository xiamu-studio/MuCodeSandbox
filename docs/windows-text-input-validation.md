# Windows 文字输入保护

2026-10-22，Windows 预览版 `0.4.66-preview.4` 增加浏览器与终端待粘贴输入框的候选输入保护。真实 Windows 输入法验收仍待手动登录隔离 Pro 测试机后继续，未计为通过。

## 已验证的行为

- 组合输入期间禁用粘贴按钮；候选确认、`isComposing`、旧式键码 229 及其他修饰键组合不会触发 Ctrl+Enter 粘贴。
- 浏览器发送期间重新编辑、开始候选输入或切换焦点时，不再执行迟到的查看器 Ctrl+V；新草稿保留。延迟取回不覆盖新输入，画面变化会取消等待请求。
- 浏览器发送前按 UTF-8 字节数限制 64 KiB，拒绝空字符。终端继续使用原有安全粘贴逻辑，不附加执行换行。
- 查看器发送粘贴键后释放 Control；终端清空草稿前再次确认内容未改变。

`npm run test:windows` 通过 181 项。`node scripts/verify-windows-text-input.ts` 的 11 项独立界面检查通过，使用真实产品组件、合成 VNC 接收端与没有 shell 的终端接收端。它通过构造 composition 事件验证竞态和候选状态保护，**不能代替操作系统输入法实测**。

## 真实输入法验收准备

`node scripts/windows-pro-ime.ts` 构建独立输入窗口，直接打包产品输入组件并记录对应源码摘要。通过 `windows-pro-probe.ts` 的 `ime-stage`、`ime-run`、`ime-inspect`、`ime-stop` 阶段，在隔离 Pro 内以普通合成用户运行。

窗口仅连接本机回环合成接收端，不读取系统剪贴板、不创建 Linux VM、不执行终端命令、不开放外部导航。它记录自身待粘贴输入框的真实事件、候选内容及接收结果，供后续逐项核对；没有 CDP 或脚本输入。活动运行禁止被覆盖，停止阶段核对进程身份并等待实际退出。窗口最多运行 30 分钟。

暂存和启动请求已完成，独立检查确认测试机内无嵌套 VM。基本会话停在 Windows 登录界面时，由用户手动完成登录，代理不自动输入密码。后续仍需验证真实拼音候选、候选确认不发送、提交后仅发送一次以及浏览器/终端最终文字；这些结果尚未取得。
