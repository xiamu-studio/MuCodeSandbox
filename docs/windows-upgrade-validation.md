# Windows 独立版本与安装升级

Windows 使用独立预览版号 `0.4.66-preview.1`。根 `package.json` 与 Mac 的 `shared/version.ts` 保持 `0.4.65`；Mac 的打包入口与发布流程未接入 Windows 版号。

## 版本与安装规则

- Windows 安装包、注册表显示版本、应用包版本、运行时启动配置与系统页使用相同的预览版号。PE 文件版本使用四段数字，例如 `0.4.66-preview.1` 对应 `0.4.66.1`。
- 预览序号按数字比较；同一基础版本的正式版高于所有预览版。各数字段有固定范围，前导零、未知后缀或无法确认的版本拒绝，不按字符串字典序推断。
- 安装器先核验所选目录和当前用户已登记安装目录，再执行旧卸载器或提取应用文件。较低的受支持版本不能覆盖较高版本；登记、包、运行清单和独立版本记录不一致时保留原件并拒绝。
- 只允许普通用户安装。程序/管理 Node 仍运行时，安装和卸载均拒绝，不终止管理进程。应用目录与凭据、数据库、运行目录和受保护 VM 磁盘相互独立；升级及卸载不包含这些用户数据目录。
- 版本检查以固定脚本载荷嵌入安装器，通过短启动命令读取，避免长编码命令被 NSIS 字符串限制截断。不会修改系统执行策略。
- 应用读取独立版本记录时验证其与应用包的一致性。Windows 成品缺少或损坏版本记录时拒绝使用猜测的版本；源码入口有独立的源码预览默认值。

以上降级检查由新安装器执行。早期 `0.4.65` 安装器没有这些检查，不应据此认为历史安装器具备同样的拦截能力；管理员或当前用户手动改写安装文件也不在版本检查的信任边界内。

## 已验证的安装链路

专用安装目录中以真实 `0.4.65` 包初始化 DPAPI 加密凭据、SQLite 原环境配置和合成用户文件，随后完成 8 项检查：旧版创建/解密原配置、运行中拒绝跨版替换、升级至 Windows 预览版、同版修复、升级至后续测试修订、拒绝较低预览版、元数据损坏拒绝覆盖，以及升级后的卸载保留原数据。

`0.4.66-preview.2` 是本轮用于验证修订排序和升级的测试包，与当前修订使用同一份代码、不同版本载荷。旧版 `0.4.65` 使用之前已经构建的实际软件包。安装器更新前后分别核验注册、应用字节和原数据摘要；新运行时还能解密旧运行时写入的原配置。本机忽略文件 `.mu-data/windows-run/upgrade-installer-lab.json` 指向报告。

## 真实隔离 Windows 验收

在网卡断开的评估 Windows 中，以合成普通用户实际安装旧版，并使用旧包内的后端创建 Linux VM、原管理密钥及加密配置。随后完成 18 项检查：

| 阶段 | 检查内容 | 检查数 |
| --- | --- | --- |
| 旧版准备 | 安装真实旧包，用其后端写入 dev canary，确认原 VM Off 和业务许可关闭 | 3 |
| 当前版升级 | 实际安装 `0.4.66-preview.1`，核验包/注册/运行时版本与原管理资料字节保留 | 2 |
| 当前版后端读回 | 新包后端解密原配置，保持原 GUID，启动原盘并读回 canary，业务许可仍关闭 | 3 |
| 后续测试修订升级 | 实际安装 `0.4.66-preview.2`，原管理资料与停止 VM 身份保留 | 2 |
| 后续后端读回 | 后续包后端解密原配置，启动同一原盘并再次读回 canary | 3 |
| 降级拒绝 | 较低的受支持预览安装器拒绝覆盖，原程序、登记及管理资料均保留 | 2 |
| 卸载与清理 | 卸载后 VM、数据库和管理文件保留；确认后仅清理合成测试 VM/盘/交换机 | 3 |

独立管理员在两次安装前后分别计算停止原盘的 SHA-256，并核验 GUID、磁盘附着路径和原登记，确认两次安装本身均未修改原 VHDX。两次正常启动产生的合法磁盘写入分别在下一次安装前重新建立基线。

本机忽略文件 `.mu-data/windows-run/clean-host-upgrade-complete.json` 指向私有回执，包含已验证的三个安装包摘要、实际阶段结果和诊断脚本摘要。最终确认已卸载测试应用、登记副本一致且为空、嵌套 VM 为零，关闭合成自动登录并确认外层 VM Off。物理宿主启动时间、Mac main 引用不变，没有访问 AI 网站。

Windows 自动测试 139 项通过，新增数字版本排序、稳定版/预览版边界、运行时记录缺失/冲突、实际安装版本检查拒绝较低/未知版本及保留损坏原件。当前未签名包另完成 6 项安装和 12 项页面检查，包括实际独立版号显示、组件恢复、存储/电源状态和桌面恢复模式往返。

不同 Windows 11 Pro、交互式安装向导、安装中断/断电恢复与更早历史版本的完整矩阵仍保留在后续验收中。当前跨版本实测的凭据/VM 登记格式均为现有格式，不据此宣称其他历史格式或跨账号迁移已经通过。
