# Windows 管理服务中断验收

2026-10-22，在独立、网卡断开的 Windows 11 Pro 测试 VM 内，实际停止并恢复 VMMS，验证当前生产后端在无法管理 Hyper-V 时关闭业务路径、保留真实停机状态，以及恢复后原盘启动的行为。物理宿主的 VMMS、网络和启动会话未改动。

## 实际结果

共 9 项实测，其中故障阶段 6 项、独立新控制进程恢复阶段 3 项。

| 场景 | 观察和核验 |
| --- | --- |
| 中断前 | 普通用户通过受保护生产代理启动真实嵌套 Linux；独立本地接收端同时观察新建 HTTPS 请求和已建立的 TLS 流 |
| 实际停止 VMMS | 管理员核对唯一内层 VM 的 GUID、标记、登记所有者和专属磁盘后，仅停止 Pro 客体中的服务；保留原 VM 工作进程句柄并直接确认其仍存活 |
| 生产监测响应 | 原联网会话进入终止状态，应用撤销访问，明确记录“停机未确认”，没有将管理服务不可用解释成 VM 已关闭 |
| 接收端观测 | VMMS 持续停止且原工作进程仍存活时，旧 TLS 连接关闭，新业务请求保持静默至少 5 秒；独立本地控制请求继续成功 |
| 服务恢复 | 原 Linux 中独立的 systemd 工作负载日志证明，接收端静默期间仍在发起失败请求；旧会话不能重开，业务许可关闭，服务恢复后不自动恢复业务连接 |
| 显式停机与原盘恢复 | 服务恢复后由产品操作确认 Off；换用新普通用户控制进程和新权限代理，启动相同 GUID、相同磁盘并读回原测试文件，业务许可保持关闭，最后删除本次专属测试资源 |

请求生产者作为 Linux 内独立服务运行并同步写入尝试日志；接收端观察连接关闭和请求计数，不以 SSH 输出停止代替网络路径关闭。HTTPS 代理只映射保留测试地址到本地回环，其他目的地拒绝，没有访问 AI 网站或真实账号。

## 诊断过程与收尾

最初的诊断客户端引用了安装包不附带的测试模块，未进入 VMMS 中断。辅助模块改为单独编译、校验并暂存在测试目录，产品安装内容保持不变。

随后观测回执更新遇到 Windows PowerShell 5 对 .NET 空字符串参数的转换问题；独立 finally 已恢复 VMMS，该轮没有计为通过。回执替换改用 NullString.Value，并在实际 Windows PowerShell 5 中验证首次写入和原子替换。确认失败客户端及任务已终止、原 VM 已 Off 后，重试复用原盘，保留失败报告；完整中断与恢复矩阵随后通过。

管理员诊断固定在该 Pro VM 的身份、磁盘和断网边界内。中断请求绑定实际普通用户进程、随机令牌及 VM GUID，拒绝其他操作和不规范身份；停止窗口有上限，错误收尾独立恢复服务。运行中的进程或未知资源不能作为失败残留自动重试。

独立收尾确认 VMMS 已恢复、内层 VM 和专属交换机为零、受保护登记双副本一致且为空、运行目录为空。停用合成自动登录后关闭 Pro 测试 VM，核对其 Off、系统盘未附着、安全启动及 TPM 保留。已安装的预览程序和独立加密配置继续保留，供后续人工桌面认证验收。

Windows 自动测试 160 项通过。新增两项执行实际 PowerShell 函数，覆盖错误令牌/进程/操作/VM 身份拒绝，以及 Windows PowerShell 5 回执替换。汇总器重新编译当前源码，逐一比较 Pro 中实际运行的 broker、runtime、manager、session、service 和 config 模块，并核对原生代理源摘要；物理宿主启动时间及 main 引用保持不变。

私有汇总保存在忽略文件 .mu-data/windows-run/pro-vmms-complete.json；账号、令牌、个人路径、日志、磁盘和回执均不提交。

## 保留的边界

本轮覆盖实际管理服务中断时的业务路径和原盘恢复。没有将其计为物理网卡切换、真实操作系统休眠唤醒、原始包绕过或多种故障叠加的完整验收；这些检查继续保留在 [Windows 工作清单](windows-work-plan.md)。Windows 仍为未签名预览版，Mac 实机回归和正式发布审查尚未完成。
